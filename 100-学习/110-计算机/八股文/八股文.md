
### 0.1.1 malloc 在内存分配失败的时候返回什么？

返回 `NULL`（空指针）。所以在每次 `malloc` 调用后，应该检查返回值是否为空，以避免对空指针解引用导致程序崩溃。

### 0.1.2 Union 在 c 语言中的合法用途正确的有哪些？
一、通过 union 进行类型双关，读取不同类型的表示。
二、节省内存，多个互斥使用的成员共享同一片内存。
三、实现简单的多态变体类型。
四、union 的成员可以有不同的对齐要求，union 的对齐等于最大成员的对齐。

### 0.1.3 This 等于 NULL 是合法的吗？还有析构函数里面 delete this 合法吗？
不合法，因为 this 是一个右值指针，右值不能赋值为 null。
在析构函数里调用 delete this 也不合法，因为 delete this 会再次调用析构函数，形成循环调用，导致反复删除自己，这显然不合理也不合法。

### 0.1.4 C 语言常用的数据，常用的基本数据类型占几个字节？
Char 占 1 个字节，short 占 2 个字节，int 占 4 个字节，long long 占 8 个字节

### 0.1.5 Inline 的作用是什么？

`inline` 关键字的主要作用有两个：

**一、向编译器建议在调用处展开函数体**（而非生成 `call` 指令），从而**消除函数调用的额外开销**（压栈、跳转、返回）。对于频繁调用的小函数（如 getter/setter），这能显著提升性能。

**二、解决 ODR（单一定义规则）问题**。`inline` 函数允许在多个翻译单元（.cpp）中重复定义，只要定义完全一致，链接器不会报重定义错误。这使我们可以把函数实现写在头文件中，每个 include 该头文件的 .cpp 都有自己的一份定义，而不会冲突。

**本质理解：**
- `inline` **只是对编译器的建议**，现代编译器会自行判断是否真正内联（`-O2` 下即使不加 `inline`，编译器也可能内联；加了也可能不内联）。
- 在现代 C++ 中，`inline` 最重要的用途不是性能优化，而是**允许在头文件中定义函数**（头文件里的普通非模板自由函数如果不加 `inline`，被多个 .cpp 包含就会链接报错）。
- **副作用**：过度内联会导致**代码膨胀（code bloat）**，增加指令缓存（I-cache）未命中率。

> 注：类定义内部直接实现的成员函数**隐式 inline**；模板函数也默认是 inline 的。

### 0.1.6 重载和虚函数分别在什么时候确定？

**重载（Overloading）** 是**编译时（静态）多态**：编译器根据参数类型和数量在编译期决定调用哪个重载版本。

**虚函数（Virtual Function）** 是**运行时（动态）多态**：通过虚函数表（vtable）在运行期根据对象的实际类型决定调用哪个函数版本，实现动态绑定。
