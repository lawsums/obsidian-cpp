## 0.2 一、修正后的完整代码
### 0.2.1 服务器端完整可运行代码
```cpp
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>

int main() {
    // 1. 获取通信文件描述符sockfd
    // AF_INET: IPv4网络协议
    // SOCK_STREAM: 面向连接的TCP协议
    // 第三个参数0: 使用协议默认的配置
    int sockfd = socket(AF_INET, SOCK_STREAM, 0);
    if (sockfd < 0) {
        perror("socket create failed");
        exit(EXIT_FAILURE);
    }

    // 2. 定义并初始化服务器地址结构体
    struct sockaddr_in serv_addr;
    bzero(&serv_addr, sizeof(serv_addr)); // 清空结构体
    serv_addr.sin_family = AF_INET;       // 协议族: IPv4
    // INADDR_ANY: 绑定所有本机网卡IP（比固定127.0.0.1更通用）
    serv_addr.sin_addr.s_addr = htonl(INADDR_ANY);
    serv_addr.sin_port = htons(8888);     // 端口号: 8888（字节序转换）

    // 3. 绑定sockfd和服务器地址
    if (bind(sockfd, (struct sockaddr*)&serv_addr, sizeof(serv_addr)) < 0) {
        perror("bind failed");
        close(sockfd);
        exit(EXIT_FAILURE);
    }

    // 4. 监听端口（转为被动套接字）
    // SOMAXCONN: 系统默认的最大等待连接队列长度
    if (listen(sockfd, SOMAXCONN) < 0) {
        perror("listen failed");
        close(sockfd);
        exit(EXIT_FAILURE);
    }
    printf("Server listening on port 8888...\n");

    // 5. 接收客户端连接（阻塞等待）
    struct sockaddr_in clnt_addr;
    socklen_t clnt_addr_len = sizeof(clnt_addr); // 必须传指针，因为accept会修改它
    bzero(&clnt_addr, sizeof(clnt_addr));
    
    // accept成功返回与客户端通信的新fd，原sockfd仍用于监听
    int clnt_sockfd = accept(sockfd, (struct sockaddr*)&clnt_addr, &clnt_addr_len);
    if (clnt_sockfd < 0) {
        perror("accept failed");
        close(sockfd);
        exit(EXIT_FAILURE);
    }

    // 打印客户端信息（字节序转换回主机序）
    printf("New client fd %d! IP: %s Port: %d\n", 
           clnt_sockfd, 
           inet_ntoa(clnt_addr.sin_addr),  // 二进制IP转字符串
           ntohs(clnt_addr.sin_port));     // 网络序端口转主机序

    // 关闭文件描述符（实际场景需循环处理连接，此处简化）
    close(clnt_sockfd);
    close(sockfd);
    return 0;
}
```

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#include <netinet/in.h>
#include <arpa/inet.h>

    }

        perror("connect failed");
        close(sockfd);
        exit(EXIT_FAILURE);
    }
    printf("Connect to server successfully!\n");

    // 关闭socket
    close(sockfd);
    return 0;
}

## 0.3 二、解答所有TODO问题
### 0.3.1 `AF_INET` 是什么意思？
`AF_INET` 是 **Address Family**（地址族）的缩写，具体含义：
- `AF`：Address Family（地址族），标识网络地址的类型；
- `INET`：指代 `Internet Protocol version 4 (IPv4)`（IPv4协议）；
- 作用：告诉操作系统，这个socket使用**IPv4网络协议**进行通信；
- 补充：`AF_INET6` 对应IPv6，`AF_UNIX` 对应本地进程间通信。

### 0.3.2 `htons` 有什么作用？
`htons` 是 **Host to Network Short** 的缩写，核心作用是**字节序转换**：
- 背景：不同CPU有不同的字节序（小端序/大端序），但网络协议规定必须使用**大端序**（网络字节序）；
- `h`：Host（主机字节序），即当前CPU的字节序；
- `n`：Network（网络字节序），固定为大端序；
- `s`：Short（短整型，2字节），对应端口号（16位）；
- 补充：
  - `htonl`：Host to Network Long（4字节，用于IP地址）；
  - `ntohs`/`ntohl`：反向转换（网络序→主机序）。

### 0.3.3 为什么需要长度属性，直接传 `sizeof(clnt_addr)` 不行吗？
**绝对不行**，必须传`socklen_t`类型的指针，原因：
- `accept` 函数的第三个参数是**输入输出参数**：
  - 输入：告诉内核传入的`clnt_addr`结构体的长度（避免内核越界写）；
  - 输出：内核返回实际接收到的客户端地址结构体的长度（比如客户端用IPv6时长度不同）；
- 如果直接传`sizeof(clnt_addr)`（值传递），内核无法修改这个值，会导致：
  1. 编译报错（参数类型不匹配，需要指针）；
  2. 即使强制转换，内核无法返回实际地址长度，可能引发内存错误；
- 本质：`socklen_t*` 是内核与用户空间的“双向通信通道”，而直接传值是“单向只读”。

## 0.5 四、使用场景举例
1. **基础TCP服务端开发**：
   - 所有基于TCP的服务（如Web服务器、聊天软件、文件传输工具）的底层核心逻辑都是这个框架；

## 0.6 总结
1. **核心流程**：TCP服务器 = `socket`创建fd → `bind`绑定地址 → `listen`监听 → `accept`接收连接；客户端 = `socket`创建fd → `connect`连接服务器。
2. **关键细节**：`AF_INET`指定IPv4协议，`htons/htonl`处理字节序，`accept`的长度参数必须传指针（输入输出特性）。
3. **易错点**：必须检查系统调用返回值、补充必要头文件、释放文件描述符，避免资源泄漏和编译错误。
