
## 0.1 协议整体架构

协议分两层抽象：

| 概念 | 作用 | 类比 |
|------|------|------|
| **Frame（帧）** | 完整的逻辑消息，包含全部业务数据 | 一封完整的信 |
| **Frog（分片包）** | 传输层的最小单元，Frame 被分片后，每个分片套上一个 Frog 头尾 | 信封（每封装一页信纸） |

**关系：** 一个 Frame 太大 → 切片 → 每片套一个 Frog → 逐个发送 → 接收方用 Frog 逐片还原 Frame。

---

## 0.2 单个 Frog 的字节布局

```
┌──────────┬──────────┬─────────────────┬──────────┬──────────┐
│  帧头     │ 数据长度  │   分片数据        │   CRC    │  帧尾     │
│ (1 byte) │ (1 byte) │ (length bytes)  │ (1 byte) │ (1 byte) │
│ 固定标志  │          │                 │ 异或校验  │含is_last │
└──────────┴──────────┴─────────────────┴──────────┴──────────┘
```

## 0.3 发送方（Sender）

```
┌─────────────────────────────────────────────────┐
│                   Frame（完整帧）                 │
│  帧头 + 数据长度 + 数据负载 + CRC + 帧尾          │
└───────────────┬─────────────────────────────────┘
                │ 若需要分片
                ▼
        ┌───────────────┐
        │   分片成 N 块   │
        └───────┬───────┘
                │
    ┌───────────┼───────────┐
    ▼           ▼           ▼
┌───────┐   ┌───────┐   ┌───────┐
│ Frog₁ │   │ Frog₂ │   │ Frogₙ │
│is_last│   │is_last│   │is_last│
│ =false│   │ =false│   │ =true │
└───────┘   └───────┘   └───────┘
    │           │           │
    ▼           ▼           ▼
  发送        发送         发送
```

**发送流程：**
1. 构建完整 Frame：拼接帧头、数据长度、数据负载、计算 CRC、追加帧尾
2. 如果 Frame 总长 > MTU，切分为多个分片
3. 每个分片包装为 Frog：加帧头 → 写本片长度 → 装本片数据 → 算 CRC → 写帧尾（`is_last` 标记是否为最后一包）
4. 依次发送各 Frog

---

## 0.4 接收方（Receiver）

**循环接收字节流，通过状态机逐字节解析 Frog：**
1. 将每个 Frog 的数据负载追加到接收缓冲区
2. 当收到 `is_last = true` 的 Frog 时，追加 `\0`，输出完整 Frame

### 0.5.2 各状态详解

| 状态 | 触发条件 | 执行动作 | 下一状态 |
|------|----------|----------|----------|
| **IDLE（空闲）** | — | 等待接收。收到字节 = 帧头标志 → 转 START | START |
| **START（开始）** | 收到帧头后第一个字节 | 读**数据长度**字段。写指针置 0，计数置 0。检查：长度 > 最大允许 → IDLE；长度 = 0 → CRC；正常 → DATA | DATA / CRC / IDLE |
| **DATA（收集数据）** | 长度 > 0 | 每收一字节：写入接收缓冲区，计数+1。当 count ≥ length → CRC | CRC |
| **CRC（校验码）** | 数据收完后 | 收到字节 = **预期 CRC**。对接收缓冲区内 `length` 字节做异或运算得**实际 CRC**。比对一致 → FOOTER；不一致 → IDLE | FOOTER / IDLE |
| **FOOTER（帧尾）** | CRC 通过后 | 收到字节 = **帧尾标志符**。检查：匹配 + `is_last` → 缓冲区末尾追加 `\0`，Frame 完整，回到 IDLE；不匹配 → IDLE | IDLE（可能带完成标志） |

### 0.5.3 关键设计点

1. **长度 = 0 的空包**：无需等待数据字节，直接从 START 跳到 CRC 状态。可用于心跳或控制信令。

2. **接收缓冲区持续累积**：每通过一个 Frog，DATA 状态写入的字节追加到缓冲区。`is_last` 标记最后一个分片，收到后才认为 Frame 完整。

3. **校验机制**：采用**异或（XOR）** 校验。对本次分片的 `length` 字节数据逐字节异或，得到实际 CRC，与 Frog 中携带的预期 CRC 比对。

4. **帧尾字节的双重含义**：
   - 标识一个 Frog 的合法结束（防止误同步）
   - 携带 `is_last` 标志，告知接收方 Frame 是否接收完整
