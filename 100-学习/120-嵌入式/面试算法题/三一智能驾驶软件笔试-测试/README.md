# 三一智能驾驶软件笔试 —— 本地自测用例

本目录对应 [[笔试—三一智能驾驶软件笔试]] 中的 1 道编程题，提供 **输入/输出测试文件** 与 **一键检测脚本**，写完代码后自行验证。

## 目录结构

```
三一智能驾驶软件笔试-测试/
├── README.md              # 本文件
├── run_tests.bat          # 一键检测入口（Windows 双击 / 命令行）
├── run_tests.ps1          # 测试脚本本体（自动发现题目与用例）
├── q1.cpp                 # 空白答题模板（已建好，直接往里写）
├── reference/             # 参考实现（用于自检测试环境）
│   └── q1.cpp             # 题目1 苹果二进制平分
└── q1-苹果二进制平分/       # 题目1 用例
    ├── test1.in / test1.out
    └── test2.in ...
```

> `test1` 是笔记里的样例，其余为补充的边界用例。`.in` 是输入，`.out` 是期望输出。
> `q1.cpp` 已自动创建为**可直接编译的脚手架**（输入读取已写好），打开填 `// TODO` 即可。

## 输入格式约定

本题题干只给了函数原型 `int maximumBenefit(int[] weights)`，没有明确 stdin 格式，这里约定：

- **第一行**：`n`，苹果个数
- **第二行**：`n` 个正整数，每个苹果的重量
- **输出**：可以平分则输出乙能拿到的最大总重量，否则输出 `-1`

> 你写的 `q1.cpp` 请按这个格式读入 / 输出（`reference/q1.cpp` 就是这么写的，可直接参考）。

## 使用方法

前置条件：已安装 **MinGW-w64**，且 `g++` 已加入 PATH。

1. **写代码**：直接在已建好的 `q1.cpp` 里填写（脚手架里 `// TODO: 在这里实现` 处）。
2. **跑测试**（cmd 或 PowerShell，双击 `run_tests.bat` 亦可）：

   ```bat
   run_tests.bat                :: 自动测试全部题目（自动找 q1.cpp）
   run_tests.bat -Problem q1    :: 只测题目1
   run_tests.bat -List          :: 只列出发现了哪些题目
   ```

   也可以指定任意源文件：

   ```bat
   run_tests.bat -Source my_solution.cpp
   ```

3. 每条用例输出 `PASS` / `FAIL` / `TODO` / `TIMEOUT`，最后给出汇总；失败时会打印期望输出与实际输出方便对照。
4. **写一道测一道**：还没实现的 `q1.cpp`（脚手架原样、程序无输出）显示 `TODO`，**不算失败**；只有写错的才 `FAIL`。

### 用参考实现自检

第一次使用建议先验证测试环境本身：

```bat
run_tests.bat -Reference
```

全部应为 `PASS`，说明编译器与用例都正常。

## 用例一览

| 用例 | 输入 | 期望输出 | 说明 |
|------|------|----------|------|
| test1 | `1 2 3` | `5` | 笔记样例，异或和为 0 |
| test2 | `1 2 4` | `-1` | 笔记样例，异或和不为 0 |
| test3 | `1 1` | `1` | 两个相同苹果 |
| test4 | `5` | `-1` | 单元素，无法分成两组 |
| test5 | `1 2 3 4 4` | `13` | 规模稍大 |
| test6 | `1 1 1 1 1` | `-1` | 奇数个相同数，异或和不为 0 |
| test7 | `5 5 5 5` | `15` | 全同值且异或和为 0 |

## 说明

- **比对规则**：忽略空白差异（多余空格、Tab、换行都不影响），但**数字序列必须完全一致**。
- **添加用例**：在 `q1-苹果二进制平分/` 里加 `testN.in` + `testN.out` 即可，脚本自动扫描（按数字排序）。
- **超时保护**：单条用例默认 10 秒超时，防止死循环卡住。
