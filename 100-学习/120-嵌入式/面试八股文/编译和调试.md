## 1.1 一、编译与构建

### 1.1.1 GCC 编译 C 程序的四个阶段是什么？每个阶段分别做了什么工作？

**难度**：简单 ｜ **来源**：芯动科技 ｜ **分类**：编译与调试
（浏览 194 · 练习 103 · 收藏 11）

GCC 编译四个阶段：

1. **预处理（`-E`）**：展开宏、处理 `#include`、条件编译，输出 `.i` 文件
2. **编译（`-S`）**：将 C 代码翻译成汇编代码，输出 `.s` 文件
3. **汇编（`-c`）**：将汇编翻译成机器码，输出 `.o` 目标文件
4. **链接（`ld`）**：将多个 `.o` 文件和库链接成可执行文件，解析符号引用

> 记忆口诀：**预编汇链**（预处理 → 编译 → 汇编 → 链接）。

| 阶段 | 选项 | 输入 | 输出 |
|---|---|---|---|
| 预处理 | `-E` | `.c` | `.i` |
| 编译 | `-S` | `.i` | `.s` |
| 汇编 | `-c` | `.s` | `.o` |
| 链接 | 无（ld） | `.o` + 库 | 可执行文件 |

### 1.1.2 GCC 编译器的常用编译选项（-O0 / -O2 / -Os / -Og）的区别

**难度**：简单 ｜ **来源**：华为 ｜ **分类**：编译与调试
（浏览 230 · 练习 122 · 收藏 8）

GCC 常用编译选项的区别：

| 选项 | 含义 | 特点 |
|---|---|---|
| `-O0` | 不优化 | 编译最快，调试最方便，代码最大最慢 |
| `-O2` | 标准优化 | 性能和体积的好平衡，生产环境常用 |
| `-Os` | 优化代码大小 | 基于 `-O2`，但关闭增大代码的优化 |
| `-Og` | 优化但保留调试体验 | 比 `-O0` 快，但能正常 GDB 调试 |

- `-Os`：嵌入式 Flash 有限时首选
- `-Og`：开发阶段推荐

**实际使用：**

- 开发调试：`-Og -g`
- 发布（嵌入式）：`-Os`
- 发布（性能优先）：`-O2`

### 1.1.3 Makefile 最终通常调用什么把可执行文件编译出来？

**难度**：简单 ｜ **来源**：诺瓦星云 ｜ **分类**：编译与调试
（浏览 165 · 练习 88 · 收藏 6）

Makefile 最终调用的是**编译器**（如 `gcc` / `arm-linux-gnueabihf-gcc`）来完成编译和链接。

**典型流程：**

```bash
gcc -c xxx.c -o xxx.o          # 编译源文件为目标文件
gcc xxx.o yyy.o -o app         # 链接所有目标文件生成可执行文件
```

Makefile 本身只是一个**自动化构建脚本**，定义了依赖关系和编译规则。`make` 工具解析 Makefile，根据文件**时间戳**判断哪些需要重新编译，然后调用相应的 shell 命令（通常就是 `gcc`）。

> 交叉编译时把 `gcc` 换成交叉编译工具链，如 `CROSS_COMPILE=arm-linux-gnueabihf-`。

## 1.2 二、GDB 调试

### 1.2.1 GDB 常用命令有哪些？

**难度**：简单 ｜ **来源**：大疆 ｜ **分类**：编译与调试
（浏览 192 · 练习 103 · 收藏 15）

GDB 常用命令速查：

| 命令 | 简写 | 作用 |
|---|---|---|
| `run` | `r` | 运行程序 |
| `break <行号/函数名>` | `b` | 设断点 |
| `next` | `n` | 单步跳过（不进函数） |
| `step` | `s` | 单步进入（进函数） |
| `continue` | `c` | 继续运行到下一个断点 |
| `print <变量>` | `p` | 打印变量值 |
| `backtrace` | `bt` | 查看调用栈 |
| `info locals` | — | 查看当前函数局部变量 |
| `info registers` | — | 查看寄存器 |
| `watch <变量>` | — | 设置数据断点，变量被修改时中断 |
| `x/<格式> <地址>` | — | 查看内存内容 |
| `list` | — | 查看源代码 |
| `frame <N>` | — | 切换到第 N 层栈帧 |
| `quit` | — | 退出 GDB |

> 嵌入式远程调试常用 `target remote :3333` 连接 OpenOCD / J-Link。

### 1.2.2 GDB 常用的调试命令有哪些？break、step、next、print、backtrace 分别是什么功能？

**难度**：简单 ｜ **来源**：芯动科技 ｜ **分类**：编译与调试
（浏览 242 · 练习 158 · 收藏 7）

GDB 常用命令：

- **`break`（`b`）**：设断点，如 `b main`、`b file.c:20`
- **`run`（`r`）**：启动程序
- **`step`（`s`）**：单步执行，进入函数
- **`next`（`n`）**：单步执行，跳过函数调用
- **`print`（`p`）**：打印变量值，如 `p x`、`p *ptr`
- **`backtrace`（`bt`）**：打印调用栈
- **`continue`（`c`）**：继续运行到下一个断点
- **`watch`**：设置数据断点，变量改变时停下

## 1.3 三、硬件调试接口与方式

### 1.3.1 JTAG 和 SWD 调试接口有什么区别？各自的优缺点是什么？

**难度**：简单 ｜ **来源**：经纬恒润 ｜ **分类**：编译与调试
（浏览 176 · 练习 80 · 收藏 10）

**JTAG**：4~5 线接口（`TCK` / `TMS` / `TDI` / `TDO` / `TRST`），支持边界扫描和调试，功能全面但占引脚多。

**SWD（Serial Wire Debug）**：ARM 专有的 2 线接口（`SWDIO` / `SWCLK`），功能和 JTAG 类似但只需 2 个引脚。

**优缺点对比：**

| 对比项 | JTAG | SWD |
|---|---|---|
| 引脚数 | 4~5 根 | 2 根 |
| 布线 | 复杂 | 简单 |
| 通用性 | 更通用（支持非 ARM 芯片） | ARM 专用 |
| 多芯片 | 支持菊花链（多芯片串联调试） | 不支持 |
| 速度 | 快 | 够用 |

- **SWD** 引脚少、布线简单、速度够用，是 **Cortex-M 调试的主流选择**。
- 大多数 ARM 开发板两种都支持。

### 1.3.2 STM32 常见的调试方式有哪些？

**难度**：简单 ｜ **来源**：小米 ｜ **分类**：STM32 / 编译与调试
（浏览 829 · 练习 421 · 收藏 52）

STM32 常见调试方式：

1. **SWD / JTAG + IDE**：通过 ST-Link / J-Link 连接，在 Keil / IAR / STM32CubeIDE 中设断点、单步、查看变量。**最常用**
2. **串口打印**：重定向 `printf` 到 UART，输出运行信息
3. **Segger RTT**：通过 J-Link 的 RTT 通道输出日志，不占用串口，速度快
4. **逻辑分析仪 / 示波器**：调试时序问题，如 SPI / I2C 波形
5. **ITM（SWO）**：通过 SWD 的 SWO 引脚输出 trace 数据
6. **LED 闪烁**：最简单的"我还活着"指示

## 1.4 四、Linux 常用命令

### 1.4.1 Linux 下打开文件的命令有哪些？

**难度**：简单 ｜ **来源**：宇视科技 ｜ **分类**：编译与调试
（浏览 167 · 练习 78 · 收藏 10）

Linux 下打开 / 查看文件的常用命令：

| 命令 | 说明 |
|---|---|
| `cat` | 显示文件全部内容（适合小文件） |
| `less` / `more` | 分页查看大文件，`less` 更强大（可上下翻页） |
| `head -n N` | 查看文件前 N 行 |
| `tail -n N` | 查看文件末尾 N 行；`tail -f` 实时追踪文件更新 |
| `vi` / `vim` | 文本编辑器，查看和编辑文件 |
| `nano` | 简单的文本编辑器 |
| `gedit` | 图形化文本编辑器 |

> 编程中打开文件的系统调用：`open()`（低级 I/O）和 `fopen()`（标准 I/O 库）。
