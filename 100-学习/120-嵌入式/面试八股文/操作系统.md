## 1.1 一、操作系统概念与对比

### 1.1.1 Linux 系统和嵌入式系统（RTOS）有哪些相似之处？

**难度**：中等 ｜ **来源**：蔚来 ｜ **分类**：操作系统 / RTOS
（浏览 380 · 练习 160 · 收藏 20）

Linux 和 RTOS 的相似之处：

1. 都提供**任务/进程调度机制**
2. 都有**内存管理**功能
3. 都支持**中断处理**
4. 都提供 **IPC 机制**（信号量、消息队列等）
5. 都有**设备驱动框架**
6. 都支持**文件系统**（RTOS 可选）

> 核心区别：**RTOS 强调确定性和实时性，Linux 强调功能丰富和通用性**。RTOS 调度更简单直接，Linux 调度更复杂但功能更强。

### 1.1.2 嵌入式 RTOS 与 PC 端操作系统（如 Linux / Windows）有什么本质区别？

**难度**：中等 ｜ **来源**：通用 ｜ **分类**：操作系统 / RTOS
（浏览 370 · 练习 132 · 收藏 17）

| 对比 | RTOS | Linux / Windows |
|---|---|---|
| **核心目标** | 确定性和实时响应 | 吞吐量和用户体验 |
| **调度策略** | 优先级抢占，确定性调度 | 公平调度，兼顾响应 |
| **内核大小** | 几 KB ~ 几百 KB | 几 MB ~ 几十 MB |
| **内存管理** | 简单（静态 / 内存池） | 复杂（虚拟内存、swap） |
| **外设支持** | 有限，按需移植 | 丰富的驱动生态 |

> RTOS 追求的是**可预测性**，PC OS 追求的是**功能丰富和公平性**。

### 1.1.3 什么是 POSIX？

**难度**：中等 ｜ **来源**：蔚来 ｜ **分类**：操作系统
（浏览 331 · 练习 159 · 收藏 19）

**POSIX**（Portable Operating System Interface）是 IEEE 制定的一套操作系统接口标准，目的是让应用程序能在不同 Unix-like 系统间**源码级移植**。

它规范了：

- **文件操作**：`open` / `read` / `write` / `close`
- **进程管理**：`fork` / `exec` / `wait`
- **线程**：`pthread` 系列
- **信号、IPC、定时器**等

Linux、macOS、QNX 等都实现了 POSIX 标准，Windows 也有部分兼容层。简单来说，遵循 POSIX 写的代码，换个系统基本能编译运行。

## 1.2 二、进程与线程调度

### 1.2.1 上下文切换时系统做了什么？

**难度**：中等 ｜ **来源**：海康威视 ｜ **分类**：操作系统 / RTOS
（浏览 454 · 练习 218 · 收藏 32）

上下文切换时系统做的事：

1. **保存当前任务上下文**：将 CPU 寄存器（通用寄存器、PC、PSR、浮点寄存器等）压入当前任务的栈
2. **更新任务控制块**：保存栈指针到 TCB
3. **选择下一个任务**：调度器决定
4. **恢复新任务上下文**：从新任务 TCB 获取栈指针，从栈中恢复所有寄存器
5. **跳转执行**：PC 恢复后继续执行新任务

### 1.2.2 信号量释放后，如何选择下一个线程？

**难度**：中等 ｜ **来源**：海康威视 ｜ **分类**：操作系统 / RTOS
（浏览 379 · 练习 183 · 收藏 26）

信号量释放（**V 操作**）后，选择下一个线程取决于**调度策略**：

- **FIFO 策略**：按等待队列顺序，最先等待的线程先被唤醒
- **优先级策略**：唤醒等待队列中优先级最高的线程

Linux 的 POSIX 信号量默认唤醒一个等待线程，具体哪个取决于内核调度器。RTOS 中通常唤醒等待队列中**优先级最高**的任务。
