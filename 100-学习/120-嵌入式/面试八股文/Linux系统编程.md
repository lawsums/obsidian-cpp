## 1.1 一、进程与线程

### 1.1.1 Linux 中的进程创建（fork / vfork / clone）的区别

**难度**：简单 ｜ **来源**：腾讯 ｜ **分类**：Linux系统编程
（浏览 163 · 练习 78 · 收藏 7）

#### 1.1.1.1 参考答案

**fork / vfork / clone 的区别：**

1. **fork**：创建子进程，完整拷贝父进程地址空间（COW 优化）
   - 子进程独立，修改互不影响
2. **vfork**：子进程共享父进程地址空间
   - 父进程阻塞直到子进程 `exec` 或 `exit`
   - 现代 Linux 已不太推荐使用
3. **clone**：最灵活，通过标志位控制共享哪些资源
   - `CLONE_VM`：共享地址空间（相当于线程）
   - `CLONE_FILES`：共享文件描述符表
   - `pthread_create` 底层就是调用 clone
4. **关系**：clone 是底层原语，fork 和 pthread 都基于它实现

### 1.1.2 Linux 中进程是什么？进程的基本属性？

**难度**：简单 ｜ **来源**：经纬恒润 ｜ **分类**：Linux系统编程
（浏览 260 · 练习 106 · 收藏 8）

#### 1.1.2.1 参考答案

Linux 中**进程**是资源分配和调度的基本单位。

**基本属性：**
- **PID**：唯一标识进程
- **PPID**：父进程 ID
- **进程状态**：运行 R、睡眠 S/D、停止 T、僵尸 Z
- **虚拟地址空间**：代码段、数据段、堆、栈、共享库映射
- **文件描述符表**：打开的文件 / socket
- **信号处理表**
- **用户 ID / 组 ID**：权限控制

每个进程有独立的**页表**（虚拟地址空间隔离）。

> 简单说：进程 = 运行中的程序 + 它占有的所有资源。

## 1.2 二、内存管理

### 1.2.1 Linux 内核空间和用户空间的区别，copy_to_user 和 copy_from_user 的作用

**难度**：简单 ｜ **来源**：龙旗科技 ｜ **分类**：Linux系统编程
（浏览 300 · 练习 79 · 收藏 6）

#### 1.2.1.1 参考答案

**内核空间**和**用户空间**是 Linux 内存管理的核心概念。

- **用户空间**：0~3GB（32 位系统），应用程序运行区域，权限受限
- **内核空间**：3~4GB，内核代码和驱动运行，有完整硬件访问权限

两者不能直接互相访问：
- `copy_to_user()`：内核 → 用户空间，安全地将数据拷贝给应用
- `copy_from_user()`：用户 → 内核空间，安全地读取用户数据

**为什么不能直接指针访问**：用户空间地址可能无效、缺页、被换出。

> 这两个函数是驱动开发中 read/write/ioctl 实现的基础。

## 1.3 三、进程间通信（IPC）

### 1.3.1 Linux 进程间通信机制有哪些？

**难度**：简单 ｜ **来源**：经纬恒润 ｜ **分类**：Linux系统编程
（浏览 193 · 练习 97 · 收藏 11）

#### 1.3.1.1 参考答案

Linux 进程间通信（IPC）机制：

- **管道（Pipe）**：半双工，父子进程间通信，`pipe()` 创建
- **命名管道（FIFO）**：有文件系统路径名，无亲缘关系进程也能用
- **消息队列**：按消息为单位收发，支持优先级
- **共享内存**：最快的 IPC，直接映射同一块物理内存
- **信号量**：进程间同步/互斥
- **信号（Signal）**：异步通知机制（如 SIGKILL、SIGTERM）
- **Socket**：支持不同主机间通信，最灵活
- **Unix Domain Socket**：同机进程间，比 TCP socket 高效

> 选型：大数据量用共享内存，结构化消息用消息队列，网络通信用 socket。

### 1.3.2 System V IPC 和 POSIX IPC 的区别？

**难度**：简单 ｜ **来源**：海康威视 ｜ **分类**：Linux系统编程
（浏览 483 · 练习 356 · 收藏 10）

#### 1.3.2.1 参考答案

**System V IPC（传统）：**
- API：`msgget/msgsnd/msgrcv`、`shmget/shmat`、`semget/semop`
- 用 key 标识，`ftok()` 生成 key
- 对象生命周期独立于进程（需手动删除 `ipcrm`）

**POSIX IPC（现代）：**
- API：`mq_open/mq_send`、`shm_open/mmap`、`sem_open/sem_wait`
- 用名字字符串标识（`/name`）
- 接口更简洁，文件描述符风格
- 可以配合 select/epoll（消息队列支持通知）

> 新项目推荐用 POSIX IPC，接口更现代更一致。

### 1.3.3 什么是 POSIX 消息队列？与 System V 消息队列的区别？

**难度**：简单 ｜ **来源**：腾讯 ｜ **分类**：Linux系统编程
（浏览 183 · 练习 54 · 收藏 6）

#### 1.3.3.1 参考答案

**POSIX 消息队列：**
- API：`mq_open`、`mq_send`、`mq_receive`、`mq_close`
- 消息有优先级，高优先级先出
- 支持 `mq_notify` 异步通知（信号或线程）
- 通过名字 `/name` 标识

**System V 消息队列：**
- API：`msgget`、`msgsnd`、`msgrcv`
- 通过消息类型筛选接收
- 用 key 标识
- 不支持异步通知

> POSIX 版本接口更现代，编程更友好。两者功能类似，新代码推荐 POSIX。

### 1.3.4 信号量和共享内存有什么区别？

**难度**：简单 ｜ **来源**：经纬恒润 ｜ **分类**：Linux系统编程
（浏览 239 · 练习 101 · 收藏 9）

#### 1.3.4.1 参考答案

**信号量**和**共享内存**解决不同问题：

- **信号量**：用于同步和互斥
  - 控制多个进程对共享资源的访问顺序
  - 本身不传递数据，只是一个计数器
  - P 操作（减）/ V 操作（加）
- **共享内存**：用于数据共享
  - 多个进程映射同一块物理内存，直接读写
  - 速度最快（无需内核拷贝）
  - 不提供同步机制，需要配合信号量使用

> 典型组合：共享内存传数据 + 信号量做互斥保护。就像一个仓库（共享内存）配一把锁（信号量）。

## 1.4 四、IO 多路复用

### 1.4.1 select、poll、epoll 的区别和适用场景？

**难度**：简单 ｜ **来源**：智元机器人 ｜ **分类**：Linux系统编程
（浏览 184 · 练习 60 · 收藏 6）

#### 1.4.1.1 参考答案

select、poll、epoll 都是 IO 多路复用机制，区别在于性能和实现：

- **select**：fd 上限 1024，每次调用要重新传入 fd 集合，O(n) 遍历
- **poll**：用链表存 fd，无数量限制，但仍是 O(n) 遍历
- **epoll**：Linux 特有，O(1) 事件通知
  - `epoll_create` → `epoll_ctl` 注册 fd → `epoll_wait` 等待事件
  - 只返回就绪的 fd 列表，不需要遍历所有

**适用场景：**
- 少量连接（<100）：select/poll 够用
- 大量连接（>1000）：必须用 epoll
- 跨平台：select 最通用

## 1.5 五、文件系统与内核

### 1.5.1 什么是 /proc 文件系统？常用的 proc 接口有哪些？

**难度**：简单 ｜ **分类**：Linux系统编程
（浏览 150 · 练习 67 · 收藏 4）

#### 1.5.1.1 参考答案

`/proc` 文件系统是 Linux 内核信息的虚拟文件接口。

- 不占磁盘空间，文件内容由内核动态生成

**常用接口：**
- `/proc/PID/status`：进程状态信息
- `/proc/PID/maps`：进程内存映射
- `/proc/PID/fd/`：进程打开的文件描述符
- `/proc/meminfo`：系统内存信息
- `/proc/cpuinfo`：CPU 信息
- `/proc/interrupts`：中断统计
- `/proc/sys/`：可读写的内核参数（如 `net.core.somaxconn`）

> `/proc` 是 Linux 系统管理和调试的核心工具，很多命令（如 top、ps）底层都读取 `/proc`。

## 1.6 六、时间与时钟

### 1.6.1 什么是 monotonic 时钟？与 realtime 时钟的区别？

**难度**：简单 ｜ **来源**：华为 ｜ **分类**：Linux系统编程
（浏览 136 · 练习 45 · 收藏 4）

#### 1.6.1.1 参考答案

**MONOTONIC 时钟**和**REALTIME 时钟**的区别：

- **CLOCK_REALTIME**：系统实时钟
  - 表示实际日期时间（如 2026-03-06 14:30:00）
  - 可以被修改（NTP 同步、手动设置 `settimeofday`）
  - 可能跳变（向前或向后）
- **CLOCK_MONOTONIC**：单调递增时钟
  - 从某个固定起点（通常是系统启动）开始计时
  - 不能被修改，只会单调递增
  - 不受 NTP 调整影响

**使用原则：**
- 计算时间间隔、超时、性能测量 → MONOTONIC
- 显示当前时间、日志时间戳 → REALTIME
