STM 32 单片机晶振一般频率多高？
{A}
STM32 常见的晶振配置：

- **外部高速晶振（HSE）**：通常是 **8MHz**（也有 12MHz、25MHz 的），通过内部 PLL 倍频到 **72MHz**（F1系列）、**168MHz**（F4系列）、**480MHz**（H7系列）等

{Q}
STM32的时钟树结构是怎样的？如何配置系统时钟？
{A}
STM32**时钟树**结构：

- **时钟源**：HSE（外部高速，通常8MHz晶振）、HSI（内部16MHz）、LSE（32.768kHz）、LSI（32kHz）
- **PLL**：将时钟源倍频，如HSE 8MHz × N / M = 168MHz
- **系统时钟**（SYSCLK）：可选HSI/HSE/PLL输出
- **总线分频**：SYSCLK → AHB分频 → APB1分频（最高42MHz）→ APB2分频（最高84MHz）

配置步骤：

1. 使能HSE，等待就绪
2. 配置PLL参数（M/N/P/Q）
3. 设置Flash等待周期
4. 选择PLL作为SYSCLK

推荐用**STM32CubeMX**图形化配置，避免出错。

{Q}
为什么 STM32 进行浮点运算通常比整数运算慢？
{A}
主要有两个原因：

1. **硬件 FPU 支持**：不是所有 STM32 都有硬件浮点单元。没有 FPU（如 Cortex-M0/M3）时，浮点运算靠**软件模拟**，需要大量指令才能完成一次运算，自然很慢
2. **即使有 FPU**（如 Cortex-M4F/M7），浮点运算的流水线周期也通常比整数运算多。整数加法1个周期，浮点加法可能需要3~5个周期

优化建议：嵌入式中能用**定点运算**（整数模拟小数）就尽量用定点；确实需要浮点时，确保编译器开启了 **FPU 硬件加速**（`-mfloat-abi=hard`）。

## 0.1 收纳箱

### 0.1.1 C 语言的内存分配有哪些方式？
C 语言内存分配主要有三种方式：

1. **静态分配**：全局变量和 `static` 变量，编译时确定大小，存储在**数据段**（.data/.bss），生命周期是整个程序
2. **栈分配**：局部变量，函数调用时自动分配，函数返回时自动释放。速度快但大小有限
3. **堆分配**：通过 `malloc()`/`calloc()`/`realloc()` 动态分配，需要手动 `free()` 释放。大小灵活但有碎片和泄漏风险

另外还有 `alloca()` 在栈上动态分配，但不推荐使用（函数返回后失效且不可移植）。

嵌入式中推荐**尽量用静态分配**，减少动态分配带来的碎片和不确定性。

### 0.1.2 const 有哪些用法？
一、修饰变量：用于让变量变成一个常量，不可被修改。

二、修饰指针：
1. Const int * p 表示指向的 int 值不能修改
2. int * const p 表示指针本身不能修改。

三、修饰函数：
1. 写在函数的返回值前面：表示这个返回值是一个常量。
2. 写在函数后面：表示函数内的各个变量不可被修改，也就是表示是一个只读函数。
3. 写在函数参数里面，表示单独对一个或多个输入的参数，不修改这些参数。

这点很重要。一般写一个库的话，函数都会写两套：一个是加 const，一个不加 const，分别表示只读函数和非只读函数。用于给自定义类型使用：如果你申请的对象是 const 对象，那么它就只能调用 const 方法；否则可以调用非 const 方法。

### 0.1.3 对于字符串，sizeof 和 strlen 的区别是什么？
strlen 和 sizeof 对字符串的区别在于：如果对象是 char* 类型，sizeof 只会返回指针大小，而 strlen 会返回到 \0 的实际字符串大小。
如果对象是 char\[] 数组类型，sizeof 会返回字符串大小加 1，因为包含 '\0'；而 strlen 会返回不带 '\0' 的实际字符串大小。

### 0.1.4 C 语言中 union 和 struct 的区别是什么？如何利用 union 判断系统字节序？union 的内存大小如何计算？
**struct**：各成员**各自占用独立的内存**，总大小是所有成员大小之和（加上对齐填充）。

**union**：所有成员**共享同一块内存**，大小等于最大成员的大小。同一时刻只有一个成员有效。

**用union判断字节序**：

`union { int i; char c; } u; u.i = 1; // u.c == 1 → 小端，u.c == 0 → 大端`

因为union中int和char共享内存起始地址，读char就是读int的最低地址字节。

**union大小计算**：取最大成员的大小，然后对齐到最大对齐要求的整数倍。例如 `union { char a[5]; int b; }` 大小是8（最大成员5字节，对齐到4的倍数→8）。

### 0.1.5 C 语言中宏定义 #define MAX (a, b) ((a)>(b)? (a): (b)) 存在什么问题？如何避免宏的副作用？
主要问题是**参数的副作用**：如果传入 `MAX(a++, b++)`，宏展开后变成 `((a++)>(b++)?(a++):(b++))`，导致较大值的变量被**自增两次**。

其他问题：

- 没有**类型检查**，传入不同类型可能有意外行为
- 宏展开可能导致**运算优先级**问题（虽然这个宏加了括号已经处理了）

**避免宏副作用的方法**：

- 使用 `inline` 函数替代宏（有类型检查，参数只求值一次）
- GCC扩展：`({ typeof(a) _a = (a); typeof(b) _b = (b); _a > _b ? _a : _b; })` 用临时变量避免多次求值
- C++中使用模板函数

总结：**能用inline函数就不用宏**，宏只在需要字符串化（#）、拼接（##）等预处理特性时使用。

### 0.1.6 C 语言的调试方法有哪些？怎么判断程序进入了死循环或出现了异常？
**常用调试方法**：
1. printf
2. GDB 断点
3. assert 断言
4. 示波器/信号分析仪
5. 看门狗检测卡死

**判断死循环**：

- GDB连上按 Ctrl+C 暂停，`backtrace` 看卡在哪
- 可疑循环中加**计数器或超时检测**
- 用**看门狗**，死循环导致喂狗超时触发复位
- **JTAG/SWD** 查看PC寄存器是否在几条指令间反复跳转

### 0.1.7 指针和数组在C语言中有什么区别？二级指针（指针的指针）怎么用？野指针是怎么产生的，如何避免？
**指针vs数组**：指针是**变量**存储地址，数组是**连续内存**，数组名大多数情况退化为首元素指针，但 `sizeof(arr)` 返回整个数组大小。

**二级指针**：指向指针的指针，常用于函数内部修改调用者的指针，如 `void alloc(int **pp) { *pp = malloc(10); }`。

**野指针产生和避免**：

- 声明未初始化 → **声明时初始化为NULL**
- free后没置NULL → **free后立即置NULL**
- 指向已释放的内存 → **注意生命周期**
