### 0.1.1 getchar_nowait() 在倒计时循环中的作用是什么？如果用户在倒计时期间不按空格，会发生什么？
getchar_nowait() 非阻塞地从 UART 环形缓冲区读取一个字符；没有字符时立即返回，不会卡住倒计时循环。

### 0.1.2 数据发送 putchar 用的是轮询还是中断？接收呢？为什么这样设计？
发送采用轮询：putchar 等待 USART SR 寄存器的 TXE(bit7) 置位后写 DR。接收采用 RXNE 中断：USART1_IRQHandler 调用 usart1_txrx()，将 DR 数据写入环形缓冲区，主循环再读取。原因是 Bootloader 输出量小，发送轮询实现简单；用户输入是异步到达的，接收中断配合环形缓冲区可以降低主循环忙碌时丢数据的风险。

### 0.1.3 行编辑中的光标移动、中间插入和中间删除如何实现？memmove 的作用是什么？
光标左移通过输出退格并减少 line_curpos，右移通过回显当前位置字符并增加 line_curpos。中间插入时，用 memmove 将光标后的字符串整体向后移动 1 字节，再写入新字符；中间删除时，用 memmove 将光标后的字符串整体向前移动 1 字节。memmove 能正确处理源和目标内存重叠，适合在同一行缓冲区内移动字符。

### 0.1.4 如果给 Bootloader 增加密钥校验以防止恶意固件，你会如何设计？
为采用非对称数字签名，构建固件时先对镜像计算 SHA-256 哈希，再用开发者密钥签名。Bootloader 将公钥固化在受保护的 Flash 区域，读取镜像后先校验 Magic 和 CRC，再对哈希验签，只有验签成功才跳转。

### 0.1.5 mymain() 中的 3 秒倒计时是怎么实现的？为什么用 cnt 计数而不是用硬件定时器？
mymain() 在 while(delay) 循环中不断调用 getchar_nowait() 检查串口输入；若没有输入则 cnt 自增，cnt 到 200000 时清零、delay--，并回退显示新的倒计时数字。它是软件忙等计时，精度依赖 CPU 主频和编译器优化。Bootloader 对 3 秒没有严格精度要求，用 cnt 可避免配置 SysTick、中断服务函数等额外复杂度。

### 0.1.7 start.s 中 SVC_Handler 用汇编实现的原理是什么？[r0, #0x2c ] 偏移量代表什么？
Svc handler 从我们的 0 x 2000 FFFC 读出 APP 下的表地址，然后读出这个地址之后，再通过添加固定偏移量 0 x 2 C 去取出 svc handler 的地址。最后通过这个 bx 跳转过去执行 svc handler。用汇编实现的原理就在于我们首先通过 0 xE 000 ED 08 我们通过寄存器获取向量表地址，存入 R 0。然后让 R 0 加上一个固定偏移量，将新地址对应的值再次存入 R 0。此时 R 0 中的值即为 svc handler 的函数指针地址。接着使用 BX R 0 指令，即可直接跳转到 svc handler 执行该函数。这是一个非常精妙的做法，涉及的汇编指令有 LDR 和 BX。

### 0.1.8 start_app() 做什么？0xE000ED08 是什么？
Start app 的输入是 app 相应的地址，我们可以先把这个地址写入到 0 xE 000 ED 08 的 VTOR 中。这个 VTOR 是 Vector Table Offset Register，也就是向量表偏移寄存器，所以我们可以利用它来重定向我们的向量表。

1. 第一步：将地址写入 VTOR。
2. 第二步：从向量表第一个位置加载 SP，从向量表第二个位置加载 app reset handler 的地址，然后跳转到 reset handler 里面，继续去执行 reset handler。

### 0.1.10 Flash 写入前为什么先擦除？NOR Flash 的物理特性是什么？
因为 Flash 只能把内存位写成 0，而不能写成 1，所以我们在写入前都要先擦除成 1。然后每次写入时，判断一下有哪些字节需要改成 0，就给它异或 1；有哪些字节需要保持为 1，就异或 0，即保持不变。
