- 这三种范式在"思考"与"行动"的组织方式上有什么本质区别？
ReAct 模式包括三步走：

1. Thought
2. Action
3. Observation

Thought 是利用当前用户给出的指令以及之前的上下文来规划之后的行动，这是大模型本身在内部自动执行的。是这个 action，action 的话是大模型利用可以调用我们给定的 tools 里面的工具，然后一并通过 API 确实发给这个大模型。然后第三步是 observation，observation 是在大模型的 API 真正执行完之后返回相应的这个结果，同时加入上下文中，方便后续继续用来 thought。

Plan and Solve 模式可能分成很多步骤，具体步骤由智能体自动决定。相比 ReAct 模式，Plan and Solve 模式最显著的特点是：一开始就规定好整个目标的步骤，在后续演算过程中，不会因为某一步的结果而改变整体计划流程。计划是一开始就定好的。

最后一个是 Reflection 模式。Reflection 模式并不独立于前两个模式之外，而是前两个模式的一种补充。它整体分为两步：
1. 执行：可以是前两个模式的任意一种。
2. 反思：这是它最独特的特点。额外引入一个实例，将刚才执行的上下文（即初稿）引入该实例，让它作为评审员来评审初稿结果，并给出反馈。
随后，将反馈和初稿再次交给第一个实例，让第一个实例进行修正迭代。迭代执行的次数由智能体自身决定，直到它认为满意或达到最大步数为止。

- 如果要设计一个"智能家居控制助手"（需要控制灯光、空调、窗帘等多个设备，并根据用户习惯自动调节），你会选择哪种范式作为基础架构？为什么？
我会选择 Reflection，将其作为基础架构，同时将 Plan and Solve 模式作为 Reflection 中 exec 执行第一步的基础架构。因为需要控制多个设备，所以一开始就需要定好代码框架，然后再进行逐步填充。这种大规模下的框架以及后续的填充，正好适合先制定一个较大的计划。此外，后续还强调了需要根据用户习惯自动调节，这说明该任务可能需要反复迭代，因此我整体选择用 Reflection 的方式。
