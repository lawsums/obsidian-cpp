**一、文档概述**

1. 文档目的  
   明确系统“数据采集—本地汇总—Mesh组网传输—云端小程序监控”全链路功能边界、技术指标和交互逻辑，为硬件设计、软件开发与云端部署提供统一的开发指引、协作规范和验收标准，保障系统按“感知—传输—监控”一体化落地，支持智能建筑应急疏散的环境数据支撑。

2. 系统核心架构  
   核心逻辑：多个ESP32感知节点实时采集建筑环境数据 → 通过Mesh自组网汇总至ESP32-S3边缘网关节点 → 网关完成初步分析与MQTT上传 → 云平台接收数据并在微信小程序中实现影子数据（镜像数据）实时监控与远程指令下发。  
   系统采用“分层感知（ESP32节点）—Mesh组网（ESP32-S3网关）—云端小程序协同”的分布式一体化架构，重点保障高可靠性、低功耗、实时性和数据完整性。

3. 适用场景  
   4. 紧急场景：火灾、烟雾超标等突发灾害的环境实时感知、数据传输与云端监控，支持早期预警；  
   5. 日常场景：建筑环境参数持续监测、设备状态巡检、历史影子数据查询与优化。

**二、核心子系统功能拆解**

（一）数据采集与传输
1. 子系统定位  
   系统核心载体，承担“多节点环境感知、本地预处理、Mesh组网汇总、云端上传与小程序监控”全链路功能。通过ESP32感知节点 + ESP32-S3网关 + 云平台小程序形成一体化数据流，覆盖建筑各楼层/区域，为后续路径决策和数字孪生提供可靠的实时环境数据支撑。

2. 硬件载体规格

| 终端类型               | 核心硬件配置                                 | 部署密度            | 核心功能边界                      |
| ------------------ | -------------------------------------- | --------------- | --------------------------- |
| ESP32感知节点（叶节点）     | ESP32控制单元、温湿度传感器、烟雾传感器、火焰传感器、电源模块、警报模块 | 每层/区域多台（危险区域加密） | 数据采集、本地预处理、Mesh通信、本地声光告警    |
| ESP32-S3边缘网关（汇总节点） | ESP32-S3处理器、Mesh模块、WiFi/以太网模块          | 1台/楼层或区域        | 数据汇总、初步分析、Mesh跨层转发、MQTT云端上传 |

3. 核心功能  
   （1）数据采集与本地处理功能  
   - 传感器数据采集：ESP32感知节点通过GPIO、UART等接口连接多类型传感器，实时采集温度（精度±0.5℃）、烟雾浓度、火焰信号等建筑环境参数；  
   - 数据本地预处理：节点对原始数据进行滤波、标准化、异常值过滤，按设定频率（正常模式低频，异常模式高频）处理；  
   - 设备状态自检：节点定时自检传感器与通信状态，异常时本地触发声光警报并上报。  

   （2）Mesh组网与数据汇总功能  
   - Mesh自组网传输：感知节点与ESP32-S3网关间采用分布式P2P Mesh模式，支持动态路由发现、最优路径选择与跨层级转发，提升网络容错性与可靠性；  
   - 数据汇总：所有ESP32节点采集的数据通过Mesh网络实时汇总至所在区域的ESP32-S3网关节点，网关完成二次整合与初步分析；  
   - 断网备份机制：网络中断时ESP32-S3网关本地缓存数据（支持一定条目），恢复后自动补传。  

   （3）云端传输与小程序监控功能（原Web管理功能已融入）  
   - 云端上传：ESP32-S3网关通过MQTT轻量级协议将汇总后的全局感知数据批量上传至云平台，确保数据可靠送达；  
   - 小程序影子数据监控：云平台部署微信小程序，实现环境参数实时仪表盘展示（温度/烟雾曲线、多楼层切换）、设备在线状态监控、历史影子数据查询与导出（Excel格式）；  
   - 报警阈值配置与通知：小程序支持自定义报警条件（如温度≥60℃、烟雾浓度超标），按区域差异化设置；触发报警时小程序弹窗提示，并可联动短信/邮件通知管理员；  
   - 远程指令下发：小程序可向ESP32-S3网关下发控制指令（如切换工作模式、触发本地警报），支持单区域/多区域调度，实现云端对感知节点的远程管控；  
   - 日志与运维：小程序记录数据上传、报警事件、指令操作日志，支持关键词查询与设备管理（节点添加、删除、状态监控）。  

   （4）本地响应功能  
   - 警报模块：烟雾/火焰超标时ESP32节点本地触发声光告警，实现环境异常的快速本地响应。

   核心目标：构建稳定、可靠、低功耗的数据感知与传输链路，为全系统提供基础数据支撑。  
   验收标准：  
   - 传感器采集精度达标，Mesh组网稳定，支持多节点动态接入与跨层转发；  
   - ESP32-S3网关数据汇总与MQTT上传可靠，断网缓存与重传机制正常；  
   - 云平台小程序实现影子数据实时监控、报警配置、远程指令下发及日志管理，界面响应流畅；  
   - 与路径算法、数字孪生子系统的接口交互稳定，数据延迟低、完整性高。

2. 路径算法处理子系统（其他同学负责）  
   核心目标：基于数据采集与传输子系统提供的实时影子数据，实现高效智能路径决策。  
   验收标准：算法计算耗时短、动态更新准确，能通过小程序接口正确接收数据并返回指令。

3. 数字孪生子系统（其他同学负责）  
   核心目标：基于数据采集与传输子系统提供的影子数据，实现物理-虚拟实时同步与可视化指挥。  
   验收标准：模型与数据同步及时，支持在孪生环境中查看影子数据并通过小程序下发指令。

**五、协作规范**

1. 数据交互格式：全系统统一采用JSON格式，字段定义由数据采集与传输子系统制定并同步给路径算法和数字孪生子系统；  
2. 接口文档：开发前制定ESP32-S3网关—小程序、小程序—算法/孪生等接口文档，提交共享平台；  
3. 定期同步：每周召开跨模块同步会，重点解决数据格式一致性、接口适配及影子数据同步等问题；  
4. 测试协同：各模块完成后联合进行集成测试，重点验证数据采集与传输子系统与上层模块的全链路可靠性与实时性。
