### 2.2.2 任务
常规任务有三个属性，也就是**名字、优先级和栈大小**
优先级并不等于重要性，有的任务可能优先级比较低，但它依然很重要。比如说空闲任务可能执行回收资源的工作，同时我们还添加一个备份资料的任务，它们优先级都很低，但是它们都很重要。

高优先级的任务有**四**个
1. 硬件初始化任务
2. 喂看门狗的任务
3. 进入和退出休眠模式的任务
4. 控制屏幕亮度的任务
中优先级的任务有**一**个，就是扫描按键
低优先级的任务有 7 个
5. lvgl 心跳的任务
6. 切换页面的任务
7. 读传感器的任务
8. 检测充电的任务
9. 处理通信(BLE//UART)消息的任务
10. 抬手亮屏检测的任务
11. 把步数设置写到 EEPROM 里面的任务

### 2.2.3 消息队列

![[Pasted image 20260814113612.png]]

消息队列是「一个信箱、一个收件人」。但有些消息要同时叫醒好几个人——比如「屏幕要亮了」，得让好几个任务都知道。这时就用另一种模式：发布-订阅。

发布者广播一条消息，名单上每个订阅者都收到。这个「名单」在代码里叫链表，而「挨个叫醒」靠的是函数指针。
```cpp
void Publisher_publish(PubSub_Publisher_t *publisher, PubSub_Message_t message) {

    SubscriberNode *node = publisher->subscribers;

    while (node != NULL) {

        node->subscriber(message);

        node = node->next;

    }

}
```

> [!info] 
>  这就是 Prompter 给我们的第一章“订阅者模式”，让我们自己编写。

![[Pasted image 20260814113846.png]]

### 2.2.4 传感器

**  
面向接口编程 / 依赖倒置**

高手不写"我用 STM32 芯片"，而是写"我依赖一个接口，谁实现它都行"。让上层依赖抽象的插座，而不是具体的芯片——这个翻转，就叫 **依赖倒置**。它让你今天能换芯片、明天能接模拟器、后天能让 AI 帮你重写底层，而 UI 一行不动。

这里就是那个 USB 插座的真身：一个装满 函数指针 的 结构体，名叫 `HWInterface`。
每一行 `.GetTimeDate = HW_RTC_Get_TimeDate`，意思都是："把某个函数的名字，插进这个插座孔里。"
``` C
HW_InterfaceTypeDef HWInterface = {
    .RealTimeClock = {
        .GetTimeDate = HW_RTC_Get_TimeDate,
        .SetDate = HW_RTC_Set_Date,
        .SetTime = HW_RTC_Set_Time,
        .CalculateWeekday = HW_weekday_calculate
    },

    .BLE = {
		.Init = HW_BLE_Init,
    	.Enable = HW_BLE_Enable,
    	.Disable = HW_BLE_Disable
    },

    .Power = {
		.power_remain = 0,
		.Init = HW_Power_Init,
        .Shutdown = HW_Power_Shutdown,
		.BatCalculate = HW_Power_BatCalculate
    },

    .LCD = {
        .SetLight = HW_LCD_Set_Light
    },
```
