# Bago Organizer（八股文面试题整理）

把用户提供的嵌入式八股文面试题材料，合理地排版并归档到 `100-学习/120-嵌入式/面试八股文/` 目录。

## 核心规则

- **只整理笔记，绝不创建复习任务**。八股文由用户手动整理进 Anki，不要调用 `create-obsidian-task`，也不要碰 `Templates/Tasks.md`。
- 目标根目录：`100-学习/120-嵌入式/面试八股文/`
- **按内容主题路由到对应文件**，而不是一律塞进同一个文件。

## 目标文件路由

| 内容主题（关键词） | 目标文件 / 章节 |
|---|---|
| Linux / 操作系统 / 系统编程（进程、线程、fork、vfork、clone、内存、文件IO、信号、IPC 等） | `Linux系统编程.md` |
| 通信协议（UART、SPI、I2C、CAN、RS232、RS485、Modbus 等） | `八股文.md` → `一、通信协议` |
| C/C++ 语言特性（static、指针、内存、模板、STL 等） | `八股文.md` → `二、C/C++ 语言` |
| RTOS / FreeRTOS / 实时性 / 任务调度 | `八股文.md` → `三、RTOS` |
| MCU / 硬件 / 外设（STM32、GPIO、DMA、定时器、中断、启动流程等） | `八股文.md` → `四、MCU 与硬件` |
| 调试 / 编译 / 开发工具 | `八股文.md` → `五、调试与工具` |
| 其他 / 拿不准 | `八股文.md` → `六、收件箱（待分类）` |

路由规则：
1. **优先放入已有的对应主题文件**（如 `Linux系统编程.md`）。
2. 若属于 `八股文.md` 已有的主题章节，加入对应章节。
3. 若是一个全新的、可能持续积累的大主题，可仿照 `Linux系统编程.md` 的先例**新建主题文件** `<主题>.md`。
4. 拿不准就放 `八股文.md` 的 `收件箱（待分类）`。

## 笔记格式

保持各文件现有的编号风格（number-headings：`# 1` / `## 1.1` / `### 1.1.1`）：

```
## X.X 一、<主题章节>

### X.X.N <问题标题>

（可选元数据行：**难度**：xxx ｜ **来源**：xxx ｜ **分类**：xxx）

<参考答案，用 Markdown 合理排版>
```

- **标题**：用问题的自然语言（如 `Linux 中的进程创建（fork/vfork/clone）的区别`）。
- **内容**：保留用户给的全部信息，重新排版——要点用有序/无序列表，代码用 ``` 代码块，关键术语用加粗或 `行内代码`。
- **插入位置**：追加到对应章节的**末尾**，编号接续现有最大值。
- 用户给了难度/来源/平台数据时，作为元数据行保留在问题标题下方。

## 执行步骤

1. **判断目标文件**：根据内容主题按上表路由。
2. **读目标文件**：先 `Read` 对应文件，了解现有章节、编号最大值与排版风格。
3. **排版内容**：把题目+答案按上述格式组织。
4. **追加写入**：用 `Edit` 在对应章节末尾插入新题，编号 = 现有最大编号 + 1。若新增章节/新建文件，按 `# 1` / `## 1.1` 的编号风格起头。
5. **不建任务**：跳过任务生成。
6. **汇报**：用 wikilink 告知用户放进了哪个文件、哪个章节、编号是多少。

## 示例

- 用户给"Linux 中的进程创建 fork/vfork/clone 的区别" → 路由到 `Linux系统编程.md` 的 `一、进程与线程`，编号接续（下一个是 `1.1.2`）。
- 用户给"RS485 和 RS232 的区别" → 路由到 `八股文.md` 的 `一、通信协议`，编号接续。
- 用户给"SPI 和 I2C 的区别" → 同属通信协议，放入 `八股文.md` `一、通信协议`。

## 注意

- 不要改动 `100-学习/120-嵌入式/面试算法题/`（那是编程题 skill 的领地）。
- 不要给八股文生成任何复习任务。
