# Exam Organizer（笔试整理 + 复习任务）

把若干道笔试题/面试题整理进一篇 Obsidian 笔记，并**联动**在 Obsidian Tasks 文件中生成一条明天的高优先级复习任务。

## 笔记结构约定

目标笔记固定采用"**题目在前，答案解析在后**"的两段式结构：

```
# 1 <标题>（如：XXX公司笔试——编程题）
**题型**：N 道编程题

# 2 题目
## 2.1 题目 1：<题名>
### 2.1.1 问题描述
### 2.1.2 输入描述
#### 2.1.2.1 示例输入
### 2.1.3 输出描述
#### 2.1.3.1 示例输出
## 2.2 题目 2：<题名>
...

# 3 答案解析
## 3.1 题目 1：<题名>
### 3.1.1 解题思路
### 3.1.2 参考代码（C++）
## 3.2 题目 2：<题名>
...
```

- 题干部分保留：问题描述 / 输入描述 / 输出描述 / 示例输入 / 示例输出，**不要**提前放解题思路或代码。
- 答案解析部分统一放在最后，每道题包含：解题思路 + 参考代码。
- 保持代码块、示例数据、格式完整，不删减内容。
- 若目标文件已存在，先 `Read` 全文，在保留原有标题编号风格（`# 1`、`## 1.1` 等）的前提下重组。

## 执行步骤

### 1. 确定目标笔记路径
- 优先使用用户给出的路径，或消息中的 `<linked_note>`。
- 否则按库内已有目录推断，例如 `100-学习/120-嵌入式/面试算法题/`。

### 2. 整理笔记
- 按上面的结构写入笔记，标题编号随层级递增。
- 完成后用 `Read` 确认内容无误（非必须，Write 成功即可）。

### 3. 生成明天的高优先级复习任务
写入 `Templates/Tasks.md`，位置为 `# 1 Inbox` 列表的**第一行**。

**格式模板**（Tasks 插件标准格式）：

```
- [ ] 完成 [[笔记名]] N 道题目 #study #algorithm #embedded ⏫ ➕ <今天> ⏳ <明天>
```

规则：
- **只写 `⏳`（scheduled/计划日期），不写 `📅`（due/截止日期）**。
- **今天 / 明天**：用系统当前日期推算。今天为 `➕` 日期，明天为 `⏳` 日期。例如今天是 `2026-08-30`，则 `➕ 2026-08-30 ⏳ 2026-08-31`。
- **优先级**：`⏫`（高优先级）。
- **标签**：`#study` 打底，按内容追加，如 `#algorithm`、`#embedded`、`#ai`。
- **描述**：用 `[[笔记名]]` wikilink 链接到刚整理/更新的笔记，写明完成几道题。
- 任务行内不要手写 `✅`、块 ID `^task-...`（Tasks 插件会自动补）。

### 4. 校验与汇报
- 校验：任务行日期正确、wikilink 指向的笔记存在、Inbox 查询块 `path includes Templates/Tasks.md` 能命中该任务。
- 汇报：用 wikilink 告知用户新建/修改了哪些文件（笔记 + Tasks）。

## 示例

用户说："帮我把这 3 道题整理到 笔试—XX公司.md，并生成明天的复习任务。"

- 笔记写到 `100-学习/120-嵌入式/面试算法题/笔试—XX公司.md`，题目在前、答案解析在后。
- `Templates/Tasks.md` 的 `# 1 Inbox` 顶部新增：
  `- [ ] 完成 [[笔试—XX公司]] 3 道编程题 #study #algorithm #embedded ⏫ ➕ 2026-08-30 ⏳ 2026-08-31`

## 注意
- 只改 `Templates/Tasks.md` 的 Inbox 区域，不动 `not done` 查询块和其他任务行。
- 若用户指定了其他日期（如"下周一""某月某日"），按用户指定覆盖"明天"默认值。
