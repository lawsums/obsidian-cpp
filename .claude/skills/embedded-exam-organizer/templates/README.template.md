# {{EXAM_NAME}} —— 本地自测用例

本目录对应 [[{{NOTE_NAME}}]] 中的 {{N}} 道编程题，提供 **输入/输出测试文件** 与 **一键检测脚本**，写完代码后自行验证。

## 目录结构

```
{{FOLDER_NAME}}/
├── README.md            # 本文件
├── run_tests.bat        # 一键检测入口（Windows 双击 / 命令行）
├── run_tests.ps1        # 测试脚本本体（自动发现题目与用例）
├── q1.cpp               # 空白答题模板（已建好，直接往里写）
├── q2.cpp               #   有几道题就有几份
├── reference/           # 参考实现（用于自检测试环境是否正常）
│   ├── q1.cpp
│   └── ...
├── q1-<题名>/           # 题目1 用例：test1.in / test1.out ...
│   ├── test1.in
│   └── test1.out
└── q2-<题名>/
    └── ...
```

> 每题的 `test1` 都是笔记里的样例，其余为补充的边界用例。`.in` 是输入，`.out` 是期望输出。
> `qN.cpp` 已自动创建为**可直接编译的脚手架**（含输入读取），打开即可写算法。

## 使用方法

前置条件：已安装 **MinGW-w64**，且 `g++` 已加入 PATH。

1. **写代码**：直接在已建好的 `q1.cpp`、`q2.cpp` …… 里填写（脚手架的 `// TODO: 在这里实现` 处）。文件已按题目数量建好，无需自己新建。
2. **跑测试**（在 cmd 或 PowerShell 中，双击 `run_tests.bat` 亦可）：

   ```bat
   run_tests.bat                :: 自动测试全部题目（每题自动找 qN.cpp）
   run_tests.bat -Problem q1    :: 只测题目1
   run_tests.bat -List          :: 只列出发现了哪些题目
   ```

   也可以指定任意源文件（跑所有题目）：

   ```bat
   run_tests.bat -Source my_solution.cpp
   ```

3. 每条用例输出 `PASS` / `FAIL` / `TODO` / `TIMEOUT`，最后给出汇总；失败时会打印期望输出与实际输出方便对照。
4. **写一道测一道**：还没实现的题目显示 `TODO`（程序无输出），**不算失败**；只有写错的才 `FAIL`。

### 用参考实现自检

第一次使用建议先验证测试环境本身（`reference\qN.cpp` 是笔记里的标准答案）：

```bat
run_tests.bat -Reference
```

全部应为 `PASS`，说明编译器与用例都正常。

## 说明

- **比对规则**：忽略空白差异（多余空格、Tab、换行都不影响），但**数字序列必须完全一致**。
- **添加用例**：在对应题目目录里加 `testN.in` + `testN.out` 即可，脚本自动扫描 `test*.in`（按数字排序）。
- **超时保护**：单条用例默认 10 秒超时，防止死循环卡住。
- 每题样例（`test1`）与笔记中的示例输入/输出一致，可直接对照。
