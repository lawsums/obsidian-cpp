# Course Note Organizer（课程知识点 / 题目整理）

把用户丢过来的**知识点原文**和/或**题目**，整理成 `100-学习/170-课程/` 下风格统一的 Obsidian 笔记。

产出**两类笔记**，互相链接：

| 类型 | 文件名 | 内容 |
|---|---|---|
| **知识点** | `<课程名>-第<X>章知识点.md` | 概念、公式、例题、易错点、速查表 |
| **作业 / 题目** | `<课程名>-第<X>章作业.md` | **题目在前，解答在后** |

对标样板（改前先读一遍）：
- 知识点：`100-学习/170-课程/随机过程/随机过程-第二章知识点.md`
- 作业：`100-学习/170-课程/随机过程/随机过程-第二章作业.md`

---

## 1. 目标位置与命名

- **根目录**：`100-学习/170-课程/`
- **课程文件夹**：`100-学习/170-课程/<课程名>/` —— 不存在就创建。

**命名规则（按优先级）**：

1. 用户/消息里给了课程名与章节号 → `<课程名>-第<X>章知识点.md` / `<课程名>-第<X>章作业.md`
2. 只给了课程名、没给章节号 → 用**主题式命名**：`<课程名>-<主题>.md`（如 `计算机通信与网络-传信速率与传码速率.md`），并把 `chapter` 字段写成主题（如「数据通信基础」）
3. 用户给了明确路径或 `<linked_note>` → 以用户的为准

> [!important] 不猜章节号
> 章节号猜错比不写更糟。用户没给就**用主题式命名**，并在汇报时说明「要改成按章命名的话给我章节号，我改名」。

**已存在同名文件时**：先 `Read` 全文，把新内容**追加/合并**进现有结构（续号、续节），**绝不覆盖**已有内容。

### 2.1 写法硬性要求

1. **公式**：一律 `$...$` / `$$...$$`。**不要**用 `\( \)`、`\[ \]`（Obsidian 里渲染不稳）。重要结论用 `\boxed{}` 框起来。
2. **Callout 只用这几种**：`[!info]` 开篇导读、`[!tip]` 技巧/变形、`[!important]` 关键区别、`[!note]` 拔高观察、`[!warning]` 易错点、`[!question]` 存疑待确认。
3. **脉络图用 ASCII 代码块**，不用 mermaid。
4. **每篇至少一张「常见情形」表格 + 一张「速查表」** —— 速查表是「要干什么 → 用什么」的两列，是复习时的主力。
5. **公式要有来处**：不只给结论，补一小段「为什么是这个式子」。
6. **术语用「」引号**，中文标点，与样板一致。
7. **不制造断链**：`[[...]]` 只写**确实存在**的笔记；不确定就写成普通文字 + 「（待补）」。
8. **原文信息零丢失**：用户给的内容全部保留，只做**结构化 + 补全**，不改写原意、不删原句里的要点。
9. **补充内容要申报**：自己加的例题、推导、章节（如「与 X 的关系」）在汇报时**逐条列出**，让用户知道哪些不是原稿里的。

````markdown
> - **形式**：题目在前，解答在后

> <原样保留残缺处，写明缺什么、待补>

---

### 1.2.1 习题 <题号>

- <同页还有但未布置的题、待补的内容>
````

### 3.1 题目整理的硬性要求

1. **题目在前，解答在后**，两段式，**不混排**。
2. 题号**与教材一致**（写「习题 2.2」而不是「第 1 题」），解答按同一题号一一对应。
3. 解答里每题末尾加一条 **`**要点**`**：点出这题的通用手法（如「交叉项全灭、只剩公共项」），这是复习时最值钱的东西。
4. 题干**完整保留**（含输入/示例、条件、编号），残缺处用 `[!question]` 标注，**不自己编题干**。推测版本要写明「按推测版本书写，补图后请核对」。
5. 用户只给题目不给答案时 → 只写 `## 1.1 题目`，「1.2 解答」留一个 `> [!question] 待补解答` 占位，**不要编答案**。

## 4. 执行步骤

1. **定课程与路径**：解析课程名、章节号/主题、笔记类型（知识点 / 作业 / 两者都要）。按第 1 节的规则生成路径，课程文件夹不存在就用 `Write` 直接建（Write 会自动创建父目录）。
2. **读样板**：若本课程文件夹已有笔记，先 `Read` 一篇，**沿用它的编号风格与既有 frontmatter 字段**（不同课程可能略有差异，以该课程已有笔记为准）。
3. **整理知识点笔记**：按第 2 节骨架写入。补例题时用**标准算法**，数字要能验算。
4. **整理作业笔记**：按第 3 节骨架写入，题目/解答严格分离。
5. **建立互链**：
   - 知识点笔记 frontmatter 的 `related:` 补上作业笔记链接；
   - 作业笔记 `## 备注` 里链回知识点，并**指明对应小节**（如「1.3.3 套路 A」）；
   - 同一课程的多篇知识点之间也互相链。
   - 链接前先确认目标文件存在，否则改文字。
6. **校验**：
   - 公式全是 `$` 写法，没有 `\( \)`；
   - 每篇有「常见情形表」+「速查表」；
   - 所有 `[[wikilink]]` 指向**真实存在**的文件；
   - 标题编号连续（`# 1` → `## 1.1` → `### 1.1.1`）。
7. **汇报**：用 wikilink 说明新建/修改了哪些文件，并**列出哪些内容是补充的**（见 2.1 第 9 条）。

---

## 5. 可选：生成复习任务

**默认不做。** 用户说「提醒我复习」「加个复习任务」「明天做」时才执行。

调用 / 遵循 **create-obsidian-task** skill（格式与写入流程以该 skill 为准），参数：

- **描述**：知识点 → `复习 [[<课程名>-第X章知识点]]`；作业 → `完成 [[<课程名>-第X章作业]] N 道题`
- **计划日期**：明天（默认；只写 `⏳`，不写 `📅`）
- **优先级**：`⏫`
- **标签**：`#study` 打底，追加课程相关标签（如 `#计算机网络`）

写入位置：`Templates/Tasks.md` 的 `# 1 Inbox` 第一行。

## 6. 示例

### 例 A：整理单个知识点

用户："帮我把这个知识点整理到 170-课程，新建文件夹『计算机通信与网络』。"（附传信速率/传码速率原文）

- 建文件夹 `100-学习/170-课程/计算机通信与网络/`
- 写 `计算机通信与网络-传信速率与传码速率.md`：frontmatter + 脉络图 + 定义 + $R_b = R_B\log_2 M$ + 常见情形表 + 3 道例题 + 5 条陷阱 + 速查表
- 汇报时说明：「例题 3 道是补的，原文没有」「文件名按主题命名，要按章命名请给章节号」

### 例 B：整理例题 + 建复习任务

用户："这几道随机过程的题整理一下，明天提醒我复习。"

- 写 `100-学习/170-课程/随机过程/随机过程-第二章作业.md`，题目在前、解答在后，每题带 `**要点**`
- 与已有的 `随机过程-第二章知识点.md` 互链：作业备注指向知识点 1.3.3 节，知识点 frontmatter 的 `related` 补上作业
- `Templates/Tasks.md` 的 `# 1 Inbox` 顶部新增：
  `- [ ] 完成 [[随机过程-第二章作业]] 8 道题 #study ⏫ ➕ 2026-09-18 ⏳ 2026-09-19`

### 例 C：只给题目没给答案

用户："这是这章的作业题，先记下来。"

- 只写 `## 1.1 题目` 段，`## 1.2 解答` 留 `> [!question] 待补解答`
- 汇报时问一句：「要我补解答吗？」

## 7. 注意

- **只新增、不覆盖**：同名笔记先 Read 再追加/合并；用户已写的内容一个字都不动。
- **不猜章节号、不编题干、不编答案** —— 这三件事猜错代价最大，宁可留 `[!question]` 占位并问用户。
- 笔记里的**图片**：用户若给了图片但没落到库里，按主系统提示的流程下载到媒体文件夹再嵌入（`![[xxx.png]]`）。
- 用户说「只要笔记，不要任务」→ 跳过第 5 节。
- 课程名/章节名照用户说的写，**不要**擅自改写成别的教材名。
