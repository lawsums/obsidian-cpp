## 0.1 3948.插入一个字母的最大子序列数

给你一个由大写英文字母组成的字符串 `s`。

你可以在字符串的 **任意** 位置（包括字符串的开头或结尾）**最多插入一个** 大写英文字母。

返回在 **最多插入一个字母** 后，字符串中可以形成的 `"LCT"` 子序列的 **最大** 数量。

**子序列** 是从另一个字符串中删除某些字符（可以不删除）且不改变剩余字符顺序后得到的一个 **非空** 字符串。

**示例 1：**

**输入：** s = "LMCT"

**输出：** 2

**解释：**

可以在字符串 `s` 的开头插入一个 `"L"`，变为 `"LLMCT"`，其中包含 2 个子序列，分别位于下标 [0, 3, 4] 和 [1, 3, 4]。

**示例 2：**

**输入：** s = "LCCT"

**输出：** 4

**解释：**

可以在字符串 `s` 的开头插入一个 `"L"`，变为 `"LLCCT"`，其中包含 4 个子序列，分别位于下标 [0, 2, 4]、[0, 3, 4]、[1, 2, 4] 和 [1, 3, 4]。

**示例 3：**

**输入：** s = "L"

**输出：** 0

**解释：**

插入一个字母无法获得子序列 `"LCT"`，结果为 0。

**提示：**

- `1 <= s.length <= 105`
- `s` 仅由大写英文字母组成。

## 0.2 Notes

### 解法对比总览

本题有两种解法：

| | 前后缀解法 | DP 解法 |
|---|---|---|
| **时间复杂度** | O(n) | O(n) |
| **空间复杂度** | O(n) | O(1) |
| **通用性** | ❌ 仅限于短模式（如 3 字符） | ✅ 可扩展到任意长度模式 |
| **代码行数** | ~40 行 | ~15 行 |

---

### DP 解法原理详解

DP 解法（Solution 中的第二个解法）的核心是 **"序列 DP + 插入收益追踪"**，在**单次 O(n) 遍历**中同时完成两件事：
1. 计算原始字符串的 `"LCT"` 子序列数
2. 计算三种插入方式各自能带来的最大增量

#### 状态变量

代码中维护了 **7 个变量**，可以分为三组：

| 分组 | 变量 | 含义 |
|------|------|------|
| 单字符 | `l` | 已遍历的 `'L'` 个数 |
| 单字符 | `c` | 已遍历的 `'C'` 个数 |
| 单字符 | `t` | 尚未遍历的 `'T'` 个数（初始为总数，遇到 T 减 1） |
| 子序列 | `lc` | 已形成的 `"LC"` 子序列数 |
| 子序列 | `ct` | 已形成的 `"CT"` 子序列数 |
| 子序列 | `lct` | 已形成的 `"LCT"` 子序列数（**原始答案**） |
| 插入收益 | `lt` | 当前**最佳插入 C 位置**能带来的增量的最大值 |

#### 核心转移逻辑

```python
for b in s:
    if b == 'L':
        l += 1                     # 新增一个 "L" 前缀
    elif b == 'C':
        lc += l                    # 前面每个 L 都和新 C 组成 "LC"
        c += 1                     # 记录 C，为后续 "CT" 做准备
    elif b == 'T':
        lct += lc                  # 前面每个 "LC" 都和新 T 组成 "LCT"
        ct += c                    # 前面每个 C 都和新 T 组成 "CT"
        t -= 1                     # 消耗一个剩余 T
    lt = max(lt, l * t)            # 当前位置插 C 的收益
```

这就是**标准的"子序列计数 DP"**：每看到一个字符，用它"延长"那些以目标模式前缀（`"L"`、`"LC"`）结尾的子序列。

#### 逐步模拟（s = "LCCT"）

```
初始: l=0, c=0, t=1, lc=0, ct=0, lct=0, lt=0

b='L': l=1, lt=max(0, 1*1)=1
       → 如果在这里插 C，左边 1 个 L × 右边 1 个 T = 1 个 "LCT"

b='C': lc+=l=1, c=1, lt=max(1, 1*1)=1
       → 1 个 "LC" 子序列: [(L0, C1)]

b='C': lc+=l=2, c=2, lt=max(1, 1*1)=1
       → 2 个 "LC" 子序列: [(L0, C1), (L0, C2)]

b='T': lct+=lc=2, ct+=c=2, t=0, lt=max(1, 1*0)=1
       → 2 个 "LCT": [(L0, C1, T3), (L0, C2, T3)]
       → 2 个 "CT":  [(C1, T3), (C2, T3)]

结果: lct + max(ct, lc, lt) = 2 + max(2, 2, 1) = 4 ✓
```

#### 三种插入方式的收益

| 插入字符 | 最佳位置 | 收益变量 | 解释 |
|----------|----------|----------|------|
| `'L'` | 最开头 | `ct` | 新增的 L 和每个已有 `"CT"` 子序列组成新的 `"LCT"` |
| `'T'` | 最末尾 | `lc` | 新增的 T 和每个已有 `"LC"` 子序列组成新的 `"LCT"` |
| `'C'` | 枚举所有位置 | `lt` | 在位置 i 插入 C，收益 = 左边 L 数 × 右边 T 数；`lt` 取全局最大 |

> **为什么 L 放最开头最优？** 因为"插入一个 L"的收益 = 这个 L 能配对的 CT 数量。放最开头意味着这个 L 在所有 C 和 T 之前，能和**所有** CT 配对，收益 = `ct`（原始串的全部 CT 子序列数）。放中间反而会失去和前面 T 或 C 的配对机会。

> **为什么 T 放最末尾最优？** 同理，放最末尾能和**所有** LC 配对，收益 = `lc`。

#### 最终公式

```
ans = orig_lct + max(插入L收益, 插入C收益, 插入T收益)
    = lct      + max(ct,          lt,          lc)
```

---

### 为什么前后缀解法不是通用解？

> **核心观点：前后缀解法"硬编码"了目标模式的结构，模式一变就失效。DP 解法是"算法思想"，天然可扩展。**

#### 前后缀解法对 "LCT" 有效的原因

因为目标模式只有 3 个字符，插入可能性只有 3 种，且其中 2 种（L 和 T）的最优位置是显然的（两端），唯一需要枚举的是 C。这属于"**碰巧**"的简单情况。

#### 如果目标模式变长（如 "ABCDEF"），前后缀解法会遇到三个致命问题：

**1. 子模式数量爆炸**

对 "LCT"，只需前缀 `L` 和后缀 `T`、`CT`。但对 "ABCDEF"，你需要预先计算**所有子模式**的前缀后缀：

- 插入 A：需要知道 `count("BCDEF")`（一个 5 字符子模式的计数）
- 插入 B：需要 `count("A"_before) × count("CDEF"_after)`
- 插入 C：需要 `count("AB"_before) × count("DEF"_after)`
- ...

一个长度为 k 的模式，子模式数量 = O($k^2$)。预处理这些前缀后缀需要 O($k^2$ · n) 的时间和空间。

**2. "两端最优"不再成立**

对 "LCT"，插入 L 放开头最优是因为"L 是最左边的字符"。但对 "ABCDEF"：
- 插入 B 的最优位置**不一定是开头**，需要在每个位置计算 `count("A"_before) × count("CDEF"_after)` 并取最大值
- k 个字符中最多有 k−2 个需要枚举位置，每个 O(n) → 总 O(k·n)

**3. 代码维护性差**

每次模式变化都要重写逻辑。而 DP 解法只需改变状态变量的定义（从追踪 "L"→"LC"→"LCT" 变为追踪任意 pattern 的 prefix）。

#### DP 解法为什么天然通用

DP 解法的本质是：

> **用状态机逐字符追踪"目标模式的所有前缀"的匹配次数。**

```
对模式 P = p1 p2 ... pk：
状态 0: 空串 ""          (总是 1)
状态 1: p1               匹配数
状态 2: p1 p2            匹配数
...
状态 k: p1 p2 ... pk    匹配数（= 目标答案）
```

每看到一个字符，用它"推进"所有能推进的状态。这不需要知道模式是什么，是一种**模式无关的算法**。插入操作的收益也是统一的计算：插入字符 X 在位置 i 处，收益 = `count(pattern_before_X)_left × count(pattern_after_X)_right`，追踪这个最大值也是模式无关的。

#### 具体验证：如果目标模式是 "leetcode"

> 假设需求从找 `"LCT"`（3 字符）变成找 `"leetcode"`（8 字符），DP 解法几乎无需改动，而前后缀解法则完全崩溃。

**1. 计数 DP：始终只需 O(k) 个变量**

```python
def count_subseq(s):
    # 追踪 "leetcode" 的 8 个前缀: l, le, lee, leet, leetc, leetco, leetcod, leetcode
    dp = [0] * 8  # dp[j] = 匹配 P[0..j] 的子序列数
    for ch in s:
        for j in range(7, -1, -1):       # 倒序遍历，避免重复字符 'e' 导致的重复计数
            if "leetcode"[j] == ch:       # 原版: if pattern[j] == ch
                dp[j] += dp[j-1] if j > 0 else 1
    return dp[7]  # 完整 "leetcode" 子序列总数
```

对 `k=3` 是 3 个变量，对 `k=8` 是 8 个变量，对 `k=100` 是 100 个变量。**状态数随模式长度线性增长。**

**2. 插入收益的通用公式**

对于要插入的字符 `X`，在模式 P 中找到所有 `P[m] == X` 的位置 m，在字符串位置 i 插入 X 的收益为：

$$\text{benefit}_X(i) = \sum_{m \,:\, P[m]=X} \underbrace{\text{left}[i][0..m-1]}_{\text{左边匹配 P[0..m-1] 的子序列数}} \;\times\; \underbrace{\text{right}[i][m+1..k-1]}_{\text{右边匹配 P[m+1..k-1] 的子序列数}}$$

然后取所有位置 i 和所有字符 X 的最大值。

**套回 "LCT" 验证**（每个字符恰好出现 1 次）：

| 插入 | P[m] | left | right | 收益 | 最优位置 |
|------|------|------|-------|------|----------|
| L | m=0 | 1（空串） | CT | = 原串已有 CT 数 | 开头 |
| C | m=1 | L | T | = L数 × T数 | 枚举取 max |
| T | m=2 | LC | 1（空串） | = 原串已有 LC 数 | 末尾 |

**套到 "leetcode"**（`'e'` 在 P 中出现 3 次，位于 m=1,2,7）：

$$\text{benefit}_e(i) = \text{left}[\texttt{"l"}](i) \times \text{right}[\texttt{"etcode"}](i) \;+\; \text{left}[\texttt{"le"}](i) \times \text{right}[\texttt{"tcode"}](i) \;+\; \text{left}[\texttt{"leetcod"}](i) \times 1$$

插入一个 `'e'`，根据它是作为"第1个e"、"第2个e"还是"第3个e"出现在结果子序列中，分别与左边和右边的不同部分配对——公式自动覆盖了所有 3 种情况。

**3. 前后缀解法的爆炸对比**

| 维度 | 模式="LCT" (k=3) | 模式="leetcode" (k=8) | 模式="alphabetically" (k=15) |
|------|------------------|-----------------------|------------------------------|
| **需追踪的子模式** | ~5 个 (L, T, LC, CT, LCT) | ~**30+** 个 | ~**120+** 个 |
| **需枚举的插入情况** | 3 种 | 6 字符 × 多匹配位 | 更多 |
| **代码修改量** | — | 需重写几乎所有逻辑 | 不现实 |
| **DP 状态变量** | 7 个 | ~15 个 | ~30 个 |

前后缀解法的本质是 **"手工列举所有 k² 种前缀×后缀组合，逐一编码"**。这对 k=3 可行（只需处理 ~5 种组合），对 k=8 已相当繁琐（~30+ 种），对 k=15 以上完全不现实。

而 DP 解法本质是 **"维护一个长度为 k 的状态机，每遇到一个字符推进所有能推进的状态"**——这是模式无关的算法，模式只是参数而非硬编码逻辑。

---

### 总结

| 维度 | 前后缀解法 | DP 解法 |
|------|-----------|---------|
| 思路 | "穷举所有插入情况，各算各的" | "单次遍历，状态机累积" |
| 对模式的依赖 | 强依赖，硬编码 | 弱依赖，模式即参数 |
| 扩展到 "ABCDEF" | 需要大量重构（O(k²n) 时间 + O(k²n) 空间） | 只需增加状态变量（O(k²·n) 时间，O(k²) 空间） |
| 推荐程度 | 适合快速过题 | **推荐理解和掌握** |

## 0.3 Solution 
```python
class Solution:
    def numOfSubsequences(self, s: str) -> int:
        # MOD = 10**9 + 7
        n = len(s)
        
        # 预处理：前缀 L 个数、后缀 T 个数
        prefix_L = [0] * (n + 1)  # prefix_L[i] = s[0..i-1] 中 L 的个数
        suffix_T = [0] * (n + 1)  # suffix_T[i] = s[i..n-1] 中 T 的个数
        
        for i in range(n):
            prefix_L[i + 1] = prefix_L[i] + (1 if s[i] == 'L' else 0)
        
        for i in range(n - 1, -1, -1):
            suffix_T[i] = suffix_T[i + 1] + (1 if s[i] == 'T' else 0)
        
        # 计算原串中 "LC" 子序列数、"CT" 子序列数、"LCT" 子序列数
        orig_LC = 0   # "LC" 子序列数
        orig_CT = 0   # "CT" 子序列数
        orig_LCT = 0  # "LCT" 子序列数
        
        for i in range(n):
            if s[i] == 'C':
                orig_LC = (orig_LC + prefix_L[i])
                orig_CT = (orig_CT + suffix_T[i + 1])
            if s[i] == 'T':
                orig_LCT = (orig_LCT + orig_LC)
        
        # 情况1：插入 L（放最前面），增量 = 原串 "CT" 子序列数
        add_L = orig_CT
        
        # 情况2：插入 T（放最后面），增量 = 原串 "LC" 子序列数
        add_T = orig_LC
        
        # 情况3：插入 C（枚举位置），增量 = max(prefix_L[i] * suffix_T[i])
        add_C = 0
        for i in range(n + 1):  # 可以插在 0~n 共 n+1 个位置
            add_C = max(add_C, prefix_L[i] * suffix_T[i])
        
        # 取三种情况的最大增量
        max_add = max(add_L, add_C, add_T)
        
        return (orig_LCT + max_add)
```


```python
class Solution:
    def numOfSubsequences(self, s: str) -> int:
        t = s.count('T')
        l = lc = lct = c = ct = lt = 0
        for b in s:
            if b == 'L':
                l += 1
            elif b == 'C':
                lc += l
                c += 1
            elif b == 'T':
                lct += lc
                ct += c
                t -= 1
            lt = max(lt, l * t)
        return lct + max(ct, lc, lt)
```
