## 0.1 334.递增的三元子序列

给你一个整数数组 `nums` ，判断这个数组中是否存在长度为 `3` 的递增子序列。

如果存在这样的三元组下标 `(i, j, k)` 且满足 `i < j < k` ，使得 `nums[i] < nums[j] < nums[k]` ，返回 `true` ；否则，返回 `false` 。

**示例 1：**

**输入：** nums = [1,2,3,4,5]
**输出：** true
**解释：** 任何 i < j < k 的三元组都满足题意

**示例 2：**

**输入：**nums = [5,4,3,2,1]
**输出：**false
**解释：**不存在满足题意的三元组

**示例 3：**

**输入：**nums = [2,1,5,0,4,6]
**输出：**true
**解释：**其中一个满足题意的三元组是 (1, 4, 5)，因为 nums[1] == 1 < nums[4] == 4 < nums[5] == 6

**提示：**

- `1 <= nums.length <= 5 * 105`
- `-231 <= nums[i] <= 231 - 1`

**进阶：**你能实现时间复杂度为 `O(n)` ，空间复杂度为 `O(1)` 的解决方案吗？

## 0.2 Notes

### 0.2.1 核心思想：贪心维护"最优前缀状态"

我们不需要记录具体的下标 `(i, j, k)`，只需要回答"**是否存在**"即可。这给了我们贪心的空间。

定义两个变量：

- **`first`**：当前遍历过的元素中，**长度为 1 的递增子序列的最小可能末尾值**。
- **`second`**：当前遍历过的元素中，**长度为 2 的递增子序列的最小可能末尾值**（即存在某个 `a < b`，且 `a` 在 `b` 之前，使得 `a ≤ first`，`b = second`）。

当遇到一个新元素 `num` 时：

| 条件 | 操作 | 含义 |
|------|------|------|
| `num > second` | **返回 true** | `first → second → num` 构成长度为 3 的递增子序列 |
| `num > first` | `second = num` | 可以接在 `first` 后面，形成一个更优的长度为 2 的子序列 |
| `num ≤ first` | `first = num` | 找到一个更小的单元素，作为未来长度 2 子序列的更好起点 |

### 0.2.2 为什么两个变量就够了？

**关键洞察**：这是一个 **LIS（最长递增子序列）问题的"提前终止"版本**。

- 标准 LIS 的 patience sorting 解法需要维护一个 `tails` 数组，其中 `tails[i]` = 长度为 `i+1` 的递增子序列的最小末尾值。
- 但本题只需要判断是否存在长度 ≥ 3 的子序列。因此我们只需要 `tails[0]`（即 `first`）和 `tails[1]`（即 `second`）。
- 一旦某个 `num` 能放在 `tails[1]` 之后（即 `num > second`），就意味着存在长度 3，可以直接返回。

### 0.2.3 最容易被质疑的点：`first` 被更新到 `second` 后面的位置怎么办？

考虑 `nums = [3, 5, 1, 6]`：

| 步骤 | `num` | `first` | `second` | 说明 |
|------|-------|---------|----------|------|
| 初始 | - | ∞ | ∞ | |
| 1 | 3 | **3** | ∞ | 长度为 1 的最小末尾 = 3 |
| 2 | 5 | 3 | **5** | 3→5 构成长度 2 |
| 3 | 1 | **1** | 5 | ⚠️ `first` 变成了 1，但 1 在数组中位于 5 **之后**！ |
| 4 | 6 | 1 | 5 | `6 > second(5)` → **返回 true** |

**为什么正确？** 虽然 `first = 1` 位于 `second = 5` 之后，但真正构成答案的是 **旧 `first = 3` → `second = 5` → `num = 6`**。把 `first` 更新为更小的 `1` 只是"提前准备"未来的更优组合，并不破坏已经记录在 `second` 中的历史信息。`second = 5` 这个值本身就隐含了"存在某个 `< 5` 的元素出现在 5 之前"这一事实。

**换句话说**：`second` 的存在性保证（existence guarantee）不依赖于当前 `first` 的值。`second` 被赋值的那一刻，就已经有一个合法的长度 2 前缀存在了。

### 0.2.4 与 LIS（最长递增子序列）的联系

本题是 LIS 长度 ≥ 3 的特判。标准 LIS 的 O(n log n) 解法维护 `tails` 数组：

```
tails[i] = 长度为 i+1 的递增子序列的最小可能末尾值
```

本题等价于：维护 `tails[0]` 和 `tails[1]`，一旦需要写入 `tails[2]` 就返回 true。


## 0.3 Solution 

### 0.3.1 Python

```python
class Solution:
    def increasingTriplet(self, nums: List[int]) -> bool:
        # first:  长度为 1 的递增子序列的最小末尾值
        # second: 长度为 2 的递增子序列的最小末尾值
        #         （存在某个 a < b 且 a 在 b 之前，使得 a <= first, b = second）
        first = float('inf')
        second = float('inf')

        for num in nums:
            if num > second:
                # first → second → num 构成长度为 3 的递增子序列
                return True
            elif num > first:
                # 可以接在 first 后面，形成更优的长度为 2 的子序列
                second = num
            else:
                # 更新最小的单元素，为未来的长度 2 子序列做准备
                first = num

        return False
```

### 0.3.2 C++

```cpp
class Solution {
public:
    bool increasingTriplet(vector<int>& nums) {
        int first = INT_MAX;   // 长度 1 的最小末尾
        int second = INT_MAX;  // 长度 2 的最小末尾

        for (int num : nums) {
            if (num > second)
                return true;
            else if (num > first)
                second = num;
            else
                first = num;
        }
        return false;
    }
};
```

> **复杂度**：时间 O(n)，空间 O(1)。每个元素只遍历一次，只用了两个额外变量。

## 0.4 思考题

### 0.4.1 思考题 1：推广到长度为 K 的递增子序列

**问题**：给定 `nums` 和整数 `K`，判断是否存在长度为 `K` 的递增子序列。要求 O(n log K) 时间，O(K) 空间。

**思路**：将"两个变量"推广为**长度为 K-1 的 `tails` 数组**。

```
tails[i] = 长度为 i+1 的递增子序列的最小可能末尾值（i = 0, 1, ..., K-2）
```

对每个 `num`，在 `tails` 中**二分查找**第一个 `≥ num` 的位置 `pos`：
- 如果 `pos == K-1`（即 `num > tails` 中所有元素），说明找到了长度为 K 的递增子序列，返回 `true`。
- 否则，更新 `tails[pos] = num`。

```python
def hasIncreasingSubsequence(nums: List[int], K: int) -> bool:
    if K <= 1:
        return True
    tails = [float('inf')] * (K - 1)  # 只需要 K-1 个槽位
    
    for num in nums:
        # 二分查找第一个 >= num 的位置
        lo, hi = 0, len(tails)
        while lo < hi:
            mid = (lo + hi) // 2
            if tails[mid] >= num:
                hi = mid
            else:
                lo = mid + 1
        
        if lo == len(tails):
            return True  # 找到了第 K 个元素
        tails[lo] = num
    
    return False
```

这正是 **patience sorting 的提前终止版本**，也是 LIS O(n log n) 解法的核心。

### 0.4.2 思考题 2：要求下标连续（子数组而非子序列）

如果要求 `i, i+1, i+2` **必须连续**（即递增的三元子**数组**），应该怎么做？

**思路**：直接检查每三个连续元素即可，O(n) 时间，O(1) 空间。

```python
def increasingTripletSubarray(nums: List[int]) -> bool:
    for i in range(len(nums) - 2):
        if nums[i] < nums[i+1] < nums[i+2]:
            return True
    return False
```

### 0.4.3 思考题 3：输出所有满足条件的三元组

**问题**：不仅要判断是否存在，还要**输出所有**满足 `i < j < k` 且 `nums[i] < nums[j] < nums[k]` 的三元组下标。

**思路**：O(n²) 解法——枚举中间元素 `j`，维护左侧小于 `nums[j]` 的集合和右侧大于 `nums[j]` 的集合。

```python
def allIncreasingTriplets(nums: List[int]) -> List[Tuple[int, int, int]]:
    n = len(nums)
    res = []
    for j in range(n):
        # 找左侧所有小于 nums[j] 的下标
        left = [i for i in range(j) if nums[i] < nums[j]]
        # 找右侧所有大于 nums[j] 的下标
        right = [k for k in range(j+1, n) if nums[j] < nums[k]]
        for i in left:
            for k in right:
                res.append((i, j, k))
    return res
```

时间复杂度 O(n²)（最坏情况下输出 O(n³) 个三元组，这是输出本身的大小下界）。

### 0.4.5 思考题 5：统计递增三元组的数目（计数版）

**问题**：统计所有满足 `i < j < k` 且 `nums[i] < nums[j] < nums[k]` 的三元组数量。

**思路**：枚举中间元素 `j`，`left_cnt` = 左侧小于 `nums[j]` 的元素个数，`right_cnt` = 右侧大于 `nums[j]` 的元素个数，贡献为 `left_cnt × right_cnt`。

可用 **Fenwick 树 / 树状数组** 在 O(n log n) 时间内完成统计。

```python
def countIncreasingTriplets(nums: List[int]) -> int:
    # 离散化
    sorted_vals = sorted(set(nums))
    rank = {v: i+1 for i, v in enumerate(sorted_vals)}  # 1-indexed
    
    n = len(nums)
    bit = FenwickTree(len(sorted_vals))
    
    # left_smaller[i] = nums[i] 左侧比它小的元素个数
    left_smaller = [0] * n
    for i in range(n):
        left_smaller[i] = bit.query(rank[nums[i]] - 1)
        bit.update(rank[nums[i]], 1)
    
    # 从右往左统计右侧比它大的元素个数
    bit = FenwickTree(len(sorted_vals))
    ans = 0
    for i in range(n-1, -1, -1):
        right_greater = bit.query(len(sorted_vals)) - bit.query(rank[nums[i]])
        ans += left_smaller[i] * right_greater
        bit.update(rank[nums[i]], 1)
    
    return ans
```
