## 0.1 1240.石子游戏 II

Alice 和 Bob 继续他们的石子游戏。许多堆石子 **排成一行**，每堆都有正整数颗石子 `piles[i]`。游戏以谁手中的石子最多来决出胜负。

Alice 和 Bob 轮流进行，Alice 先开始。最初，`M = 1`。

在每个玩家的回合中，该玩家可以拿走剩下的 **前** `X` 堆的所有石子，其中 `1 <= X <= 2M`。然后，令 `M = max(M, X)`。

游戏一直持续到所有石子都被拿走。

假设 Alice 和 Bob 都发挥出最佳水平，返回 Alice 可以得到的最大数量的石头。

**示例 1：**

**输入：**piles = [2,7,9,4,4]
**输出：**10
**解释：**如果一开始 Alice 取了一堆，Bob 取了两堆，然后 Alice 再取两堆。Alice 可以得到 2 + 4 + 4 = 10 堆。
如果 Alice 一开始拿走了两堆，那么 Bob 可以拿走剩下的三堆。在这种情况下，Alice 得到 2 + 7 = 9 堆。返回 10，因为它更大。

**示例 2:**

**输入：**piles = [1,2,3,4,5,100]
**输出：**104

**提示：**

- `1 <= piles.length <= 100`
- `1 <= piles[i] <= 104`

## 0.2 Notes

### 0.2.1 核心洞察：零和博弈 + M 可变

这道题与 [[1522.石子游戏 III.md|石子游戏 III]] 的核心差异在于 **M 是动态变化的**（$M = \max(M, X)$），因此 $f_i$ 不能只用一维——必须引入第二维记录当前的 $M$ 值。

但相同的是**"当前玩家"视角**：$f(i, m)$ 永远代表"当前玩家"从位置 $i$、参数 $m$ 开始，能获得的最大石子数。

### 0.2.2 状态定义

设 `piles` 长度为 $n$：

- **$dp[i][m]$**：从第 $i$ 堆开始，当前 $M = m$，**当前玩家**能获得的最大石子总数。

初始状态即为 $dp[0][1]$，即 Alice 从第 0 堆、$M=1$ 开始时能获得的最大石子数。

### 0.2.3 递推方程

在当前回合，玩家可以拿走前 $X$ 堆，其中 $1 \leq X \leq 2m$。拿走 $X$ 堆后：

- 当前玩家**立即**获得这 $X$ 堆的石子（即 `piles[i] + ... + piles[i+X-1]`）
- 剩余石子从 $i+X$ 开始，**M 更新为** $\max(m, X)$
- **对手**成为新的"当前玩家"，对手最优能拿 $dp[i+X][\max(m, X)]$ 颗石子

由于零和博弈，当前玩家能从剩余石子中分到：$\text{suffix\_sum}[i+X] - dp[i+X][\max(m, X)]$

因此：

$$
dp[i][m] = \text{suffix\_sum}[i] - \min_{1 \leq X \leq 2m}\Big( dp[i+X][\max(m, X)] \Big)
$$

即：总剩余减去对手能拿的**最小值**，等价于自己拿的**最大值**。

### 0.2.4 手算推演 — 以 `piles = [2, 7, 9, 4, 4]` 为例

```
suffix_sum = [22, 20, 13, 8, 4, 0]
                                       
dp[0][1] 可选的 X: 1 或 2
                                                      
  选 X=1: M' = max(1,1) = 1                       当前拿: piles[0]=2
         opponent = dp[1][1]                        剩余: suffix_sum[1]=20
         当前总得 = 22 - dp[1][1]

  选 X=2: M' = max(1,2) = 2                       当前拿: piles[0]+piles[1]=9  
         opponent = dp[2][2]                        剩余: suffix_sum[2]=13
         当前总得 = 22 - dp[2][2]

dp[0][1] = 22 - min(dp[1][1], dp[2][2])
```

最终 $dp[0][1] = 10$，即 Alice 能拿到的最大石子数。

### 0.2.5 与石子游戏 III 的对比

| | 石子游戏 III | 石子游戏 II |
|---|---|---|
| **拿取范围** | 固定 1/2/3 堆 | $X \in [1, 2M]$，**M 可变** |
| **DP 维度** | 一维 $f_i$ | 二维 $dp[i][m]$ |
| **递推** | $f_i = \text{suf}[i] - \min(f_{i+1}, f_{i+2}, f_{i+3})$ | $dp[i][m] = \text{suf}[i] - \min\limits_{X=1}^{2m} dp[i+X][\max(m,X)]$ |
| **核心思想** | "当前玩家"视角 | 同左 + M 状态维度 |

### 0.2.6 复杂度分析

- **状态数**：$i$ 有 $n$ 个取值，$m$ 理论上可达 $n$，但实际由于 $M$ 翻倍增长，大部分状态不会访问 → 约 $O(n^2)$
- **每次转移**：枚举 $X \in [1, 2m]$ → $O(n)$
- **总复杂度**：$O(n^3)$，由于 $n \leq 100$，完全可行。

记忆化搜索（top-down）比迭代 DP（bottom-up）更自然，因为不是所有 $(i, m)$ 组合都会被访问。

## 0.3 Solution 
```python
from typing import List

class Solution:
    def stoneGameII(self, piles: List[int]) -> int:
        n = len(piles)
        
        # 1. 预处理后缀和，方便 O(1) 计算从 i 到末尾的总和
        suffix_sum = [0] * (n + 1)
        for i in range(n - 1, -1, -1):
            suffix_sum[i] = suffix_sum[i + 1] + piles[i]
            
        # 2. 记忆化字典，用来存储已经计算过的 dp[i][m] 状态，避免重复计算
        memo = {}
        
        # 3. 定义递归函数
        def dp(i, m):
            # 如果已经越界，说明没有石子可拿了
            if i >= n:
                return 0
            
            # 如果当前状态已经计算过，直接返回结果
            if (i, m) in memo:
                return memo[(i, m)]
            
            # 如果剩下的石子堆数 <= 2M，当前玩家可以直接全部拿走
            if i + 2 * m >= n:
                return suffix_sum[i]
            
            # 4. 状态转移：当前玩家能拿的最大值 = 剩余总和 - 对手能拿的最大值
            # 对手能拿的最大值，就是我们在所有合法的 X 中，寻找 dp(i + x, max(m, x)) 的最大值
            min_opponent = float('inf')
            for x in range(1, 2 * m + 1):
                # 对手在下一轮的状态
                opponent_val = dp(i + x, max(m, x))
                min_opponent = min(min_opponent, opponent_val)
                
            # 当前玩家的最大收益
            result = suffix_sum[i] - min_opponent
            memo[(i, m)] = result
            return result
        
        # 游戏从下标 0 开始，初始 M = 1
        return dp(0, 1)
```
