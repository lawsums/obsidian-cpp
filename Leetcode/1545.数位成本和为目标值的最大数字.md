## 0.1 1545.数位成本和为目标值的最大数字

给你一个整数数组 `cost` 和一个整数 `target` 。请你返回满足如下规则可以得到的 **最大** 整数：

- 给当前结果添加一个数位（`i + 1`）的成本为 `cost[i]` （`cost` 数组下标从 0 开始）。
- 总成本必须恰好等于 `target` 。
- 添加的数位中没有数字 0 。

由于答案可能会很大，请你以字符串形式返回。

如果按照上述要求无法得到任何整数，请你返回 "0" 。

**示例 1：**

**输入：**cost = [4,3,2,5,6,7,2,5,5], target = 9
**输出：**"7772"
**解释：**添加数位 '7' 的成本为 2 ，添加数位 '2' 的成本为 3 。所以 "7772" 的代价为 2*3+ 3*1 = 9 。 "977" 也是满足要求的数字，但 "7772" 是较大的数字。
 **数字     成本**
  1  ->   4
  2  ->   3
  3  ->   2
  4  ->   5
  5  ->   6
  6  ->   7
  7  ->   2
  8  ->   5
  9  ->   5

**示例 2：**

**输入：**cost = [7,6,5,5,5,6,8,7,8], target = 12
**输出：**"85"
**解释：**添加数位 '8' 的成本是 7 ，添加数位 '5' 的成本是 5 。"85" 的成本为 7 + 5 = 12 。

**示例 3：**

**输入：**cost = [2,4,6,2,4,6,4,4,4], target = 5
**输出：**"0"
**解释：**总成本是 target 的条件下，无法生成任何整数。

**示例 4：**

**输入：**cost = [6,10,15,40,40,40,40,40,40], target = 47
**输出：**"32211"

**提示：**

- `cost.length == 9`
- `1 <= cost[i] <= 5000`
- `1 <= target <= 5000`

## 0.2 Notes

### 0.2.1 核心思路：完全背包 + 字典序最大化

本题是一个**完全背包（Unbounded Knapsack）**问题，但 DP 值不是整数而是**字符串**，比较逻辑也不再是简单的数值大小，而是**长度优先 + 字典序**。

#### 0.2.1.1 为什么从 9 → 1 倒序遍历？

从大到小（`9 → 1`）倒着加，有两个好处：

- **计算方便**：字符串拼接时，`dp[j-c] + str(digit)` 等价于把新数位追加到末尾，自然得到正确数字。高位在前、低位在后，字符串天然就是数字的正确表示。
- **字典序保证**：从 9 往 1 遍历数位，意味着大的数字**先被尝试放入**。在背包容量（cost）相同的情况下，先出现的组合字典序更大。因此倒序遍历天然保证了：**花费相同成本时，结果字典序最大**。

#### 0.2.1.2 DP 的比较逻辑：长度 > 字典序

两个字符串代表两个数字时，比较规则是：
1. **位数多的更大**（`len(a) > len(b)` → `a` 代表的数字更大）
2. **位数相同**时，按字典序比较（`a > b` 即字符串逐位比较）

```python
if len(new_val) > len(dp[j]) or (len(new_val) == len(dp[j]) and new_val > dp[j]):
    dp[j] = new_val
```

这正是整数比较的本质：`7772` > `977`（4位数 > 3位数），`7772` > `7771`（位数相同时字典序）。

#### 0.2.1.3 DP 三要素

| 要素 | 说明 |
|------|------|
| **状态** | `dp[j]` = 恰好花费成本 `j` 能组成的最大数字（字符串） |
| **初始化** | `dp[0] = ""`（空串），其余 `"0"`（不可达标记） |
| **转移** | `dp[j] = max(dp[j], dp[j - cost[d]] + str(d))`，其中 `d = 9→1` |

#### 0.2.1.4 完全背包的标准模板

外层遍历**物品**（数位 9→1），内层**正序**遍历容量（允许同一数位无限次选取）：

```
for digit in 9..1:
    c = cost[digit - 1]
    for j in c..target:
        dp[j] = better(dp[j], dp[j-c] + str(digit))
```

## 0.3 Solution 
```python
        #  从大到小倒着加，这样比较方便。因为倒着加的话，我们直接乘 10，把之前的数乘 10 再加上当前位，就得到这个总和的数了，所以比较方便计算。
        # 要方便计算呢，我们这里的 DP 就把这个总和的数当做 DP 值加进来，然后每个格子取它的当前最大值和这个新的总和取最大值。
        # 为什么我们从 9~1 这个顺序来取呢？因为从 9~1 这个顺序来取，我们会把这个大的数、大的数位的数先放在前面。那么从字典序的角度来看，把大的放在前面肯定是比把大的放在后面的要大，所以我们这样首先保证了字典序是最大的，保证了在这个选取的代价相同的时候，字典序是最大的。
        # 然后在代价相同的情况下，我们添加的成本可能不一样。在这个成本一样的情况下呢，我们添加的位数可能是不同的。所以我们的 DP 相当于维护的是位数最大然后字典序最大，同时满足就是最大的整数的。

class Solution:
    def largestNumber(self, cost: List[int], target: int) -> str:
        # dp[j] 表示恰好花费成本 j 能组成的最大数字（字符串形式）
        # 初始化为 "0" 表示不可达，"0" 同时也是无法组成时的返回值
        dp = ["0"] * (target + 1)
        dp[0] = ""  # 成本为 0 时，空字符串（还没添加任何数位）

        # 从 9 到 1 倒序遍历数位，保证大数字优先放在高位
        for digit in range(9, 0, -1):
            c = cost[digit - 1]  # 数位 digit 的成本
            # 完全背包：正序遍历容量（允许同一数位重复选取）
            for j in range(c, target + 1):
                if dp[j - c] != "0":  # 前驱状态可达
                    new_val = dp[j - c] + str(digit)
                    # 位数更多的一定更大；位数相同时，因为从 9→1 遍历，
                    # 先出现的字典序更大，所以用 >= 即可
                    if len(new_val) > len(dp[j]) or (len(new_val) == len(dp[j]) and new_val > dp[j]):
                        dp[j] = new_val

        return dp[target]
```
