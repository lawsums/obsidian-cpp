## 0.1 1934.替换字符串中的括号内容

给你一个字符串 `s` ，它包含一些括号对，每个括号中包含一个 **非空** 的键。

- 比方说，字符串 `"(name)is(age)yearsold"` 中，有 **两个** 括号对，分别包含键 `"name"` 和 `"age"` 。

你知道许多键对应的值，这些关系由二维字符串数组 `knowledge` 表示，其中 `knowledge[i] = [keyi, valuei]` ，表示键 `keyi` 对应的值为 `valuei` 。

你需要替换 **所有** 的括号对。当你替换一个括号对，且它包含的键为 `keyi` 时，你需要：

- 将 `keyi` 和括号用对应的值 `valuei` 替换。
- 如果从 `knowledge` 中无法得知某个键对应的值，你需要将 `keyi` 和括号用问号 `"?"` 替换（不需要引号）。

`knowledge` 中每个键最多只会出现一次。`s` 中不会有嵌套的括号。

请你返回替换 **所有** 括号对后的结果字符串。

**示例 1：**

**输入：**s = "(name)is(age)yearsold", knowledge = [["name","bob"],["age","two"]]
**输出：**"bobistwoyearsold"
**解释：**
键 "name" 对应的值为 "bob" ，所以将 "(name)" 替换为 "bob" 。
键 "age" 对应的值为 "two" ，所以将 "(age)" 替换为 "two" 。

**示例 2：**

**输入：**s = "hi(name)", knowledge = [["a","b"]]
**输出：**"hi?"
**解释：**由于不知道键 "name" 对应的值，所以用 "?" 替换 "(name)" 。

**示例 3：**

**输入：**s = "(a)(a)(a)aaa", knowledge = [["a","yes"]]
**输出：**"yesyesyesaaa"
**解释：**相同的键在 s 中可能会出现多次。
键 "a" 对应的值为 "yes" ，所以将所有的 "(a)" 替换为 "yes" 。
注意，不在括号里的 "a" 不需要被替换。

**提示：**

- `1 <= s.length <= 105`
- `0 <= knowledge.length <= 105`
- `knowledge[i].length == 2`
- `1 <= keyi.length, valuei.length <= 10`
- `s` 只包含小写英文字母和圆括号 `'('` 和 `')'` 。
- `s` 中每一个左圆括号 `'('` 都有对应的右圆括号 `')'` 。
- `s` 中每对括号内的键都不会为空。
- `s` 中不会有嵌套括号对。
- `keyi` 和 `valuei` 只包含小写英文字母。
- `knowledge` 中的 `keyi` 不会重复。

## 0.2 Notes

### 0.2.1 核心思路：把「是否在括号内」做成扫描状态

整个题目就是一个**单次扫描 + 查表**：

1. 先用 `knowledge` 建哈希表 `key → value`，O(m)；
2. 从左往右扫 `s`，只有两种处境：
   - **不在括号内**：当前字符原样写进结果；
   - **在括号内**：当前字符攒进 key，直到撞上 `)`，拿 key 查表 —— 命中就写 `value`，没命中就写 `?`。
3. `(` 和 `)` 本身都**不写进结果**（它们只是定界符）。

所以这题没有算法难度，考的是**把这台状态机写干净**。下面三种解法做的事完全一样，区别只在「状态放在哪」。

### 0.2.2 三种写法：状态分别放在哪

| | 状态怎么表示 | key 怎么表示 | 特点 |
| --- | --- | --- | --- |
| 解法一（下标） | `int i`，遇到 `(` 就 `i++` 进内层 `while` | 临时 `std::string tmp` | 最好懂；签名与官方模板一致 |
| 解法二（指针） | `const char* str`，靠 `'\0'` 当结尾哨兵 | `string_view` 圈区间，零拷贝 | 最快；但依赖 C++20 和哨兵 |
| 解法三（Python） | 交给 `str.format_map` 内部 | 库内部 | 两行；有前提，见 0.2.3 |

==解法一和解法二其实是同一套逻辑==：遇到 `(` 就把指针/下标推进一步，然后一直吃到 `)`。区别只是"推进一个 `int`"还是"推进一个指针"，以及 key 是**拷贝成 string** 还是**记成 view**。

解法三是另一条路：`(` → `{`、`)` → `}` 之后，整串就变成了一个合法的 `format` 模板，`{name}` 这种占位符由 `format_map` 去查表 —— **状态机整个外包给标准库**。而 `defaultdict(lambda: '?', knowledge)` 让查不到的表项自动返回 `?`，连"未命中"分支都省了。

### 0.2.3 实测踩坑（都亲手验过）

**① `while (s[i] != ')')` 不判边界是安全的 —— 但只因为这题的约束**

题目保证「每一个 `(` 都有对应的 `)`」且「无嵌套括号」，所以内层循环一定能停下来。换成一道括号可能不配对的题，这里直接越界。

另外注意：内层 `while` 退出时 `i` **停在 `)` 上**，这个 `)` 不能输出 —— 而外层 `for` 的 `i++` 正好把它吃掉，这个"错位"是故意的，不是 bug。

**② `string_view{begin, prev(str)}` 是 C++20 才有的（实测 C++17 编译失败）**

两个指针的写法走的是 `basic_string_view(It first, End last)` 这个**迭代器对构造函数，C++20 才加入**。C++17 下编译器会把它往 `(const char*, size_type)` 上套，直接报：

```
error: invalid conversion from 'const char*' to 'std::basic_string_view<char>::size_type'
```

LeetCode 现在用 C++20/23 没问题；本地要是 C++17 工程，得改成显式算长度：

```cpp
string_view{begin, size_t(prev(str) - begin)}
```

**③ `'\0'` 当哨兵是"能跑但越界"的写法**

```cpp
for (auto str = s.begin();;) { auto ch = *str++; ... }
```

循环**先读、后判**，读到末尾之后还要再读一次 `'\0'` 才知道结束。`s` 是 `string_view`，按标准 `data()[size()]` 是越界的。它能跑，是因为 LeetCode 传进来的 `s` 背后是 `std::string`，而 C++11 起 `data()[size()]` 保证是 `'\0'`。==真正没有空字符结尾的 `string_view` 上，这就是 UB。== 稳妥些就把长度并进循环条件。

**④ 查表查了两次**

解法一里：

```cpp
if (mp.count(tmp)) { ans += mp[tmp]; }
```

`count` 和 `[]` 各做一次完整哈希查找。写成 `if (auto it = mp.find(tmp); it != mp.end()) ans += it->second;` 只查一次。数据小看不出差别，是个习惯问题。

**⑤ `int i` 撞 `s.size()` 会警告**

`-Wall` 下 `for (; i < s.size(); i++)` 报 `comparison of integer expressions of different signedness`。约束 `|s| <= 1e5` 不会真溢出，但写 `int n = s.size()` 或 `size_t i` 更干净。

**⑥ Python 版有两个隐藏前提**

- `(`/`)` 换成 `{`/`}` 之所以成立，是因为约束保证 `s` **只含小写字母和圆括号**，没有别的 `{` `}` 会被 `format_map` 误当成占位符；键只有小写字母，也不会踩到 `!`/`:` 这类格式符。
- ==空键会炸==：实测 `s = "()"` 抛 `ValueError: Format string contains positional fields`（`{}` 被当成自动编号的定位参数，而 `format_map` 不接受定位字段）。题目保证「每对括号内的键都不会为空」，所以过得了；但这是它唯一比扫描法脆的地方。

### 0.2.4 复杂度与实测

- **时间** O(m + |s|)：建表 O(m)，扫描每个字符恰好访问一次。严格说每次查表还要哈希 key（长度 ≤ 10），但这部分也被括号内字符总数 ≤ |s| 罩住了。
- **空间** O(m)（哈希表）+ O(|s|)（结果串）。
- 同机实测（`|s| = 4·10⁵`，`m = 10⁵`，`-O2`）：下标法 5~7 ms，`string_view` 法 2~4 ms。
- 省下来的主要是**分配**：`string_view` 版的表里存的是指向 `knowledge` 的引用，查询时也不构造临时串；下标法每个括号对都要建一个 `tmp`（好在 ≤10 字符，落在 libstdc++ 的 SSO 缓冲区内，不会真的去堆上要内存）。

## 0.3 Solution 
**解法一：C++ 下标扫描 + 哈希表 —— O(m + |s|) 时间 / O(m) 空间（主解法）**

```cpp
class Solution {
public:
    string evaluate(string s, vector<vector<string>>& knowledge) {
        unordered_map<string, string> mp;
        for (const auto &p : knowledge) {
            string key = p[0], val = p[1];
            mp[key] = val;
        }

        int i = 0;
        string ans = "";
        for (; i < s.size(); i++) {
            // 如果匹配到这个小括号的话，就进入匹配模式
            if (s[i] == '(') {
                i++;
                string tmp = "";
                while (s[i] != ')') {
                    tmp.push_back(s[i++]);
                } // s[i] == ')', tmp = key
                // 如果存在这个键，那么就是掭加到结果里
                if (mp.count(tmp)) {
                    ans += mp[tmp];
                } else {
                    ans.push_back('?');
                }
            } else {
                ans.push_back(s[i]);
            }
        }

        return ans;
    }
};
```

**解法二：C++ `string_view` 零拷贝扫描 —— 表里存引用，查询不建临时串**

```cpp
class Solution {
public:
    static string evaluate(const string_view s, const vector<vector<string> > &knowledge) {
        string result;
        result.reserve(s.size() * 2);
        unordered_map<string_view, string_view> table;
        table.reserve(knowledge.size());
        for (auto &vec: knowledge) {
            table[vec.front()] = vec.back();
        }
        for (auto str = s.begin();;) {
            auto ch = *str++;
            if (ch == '(') {                
                for (auto begin = str;;) {
                    if (*str++ == ')') {
                        const auto it = table.find(string_view{begin, prev(str)});
                        if (it != table.end()) {
                            result += it->second;
                        }
                        else {
                            result.push_back('?');
                        }
                        break;
                    }
                }
            }
            else if (ch == '\0') {
                return result;
            }
            else {
                result.push_back(ch);
            }
        }
    }
};
```

> ⚠️ 这版有三处要留意（详见 0.2.3）：`string_view{begin, prev(str)}` **需要 C++20**；`'\0'` 哨兵依赖 `s` 背后是 `std::string`；`const string_view s` 这个签名与 LeetCode 要求的 `string evaluate(string, vector<vector<string>>&)` **不一致**，交题时要改回 `string s`（或套一层转换）。

**解法三：Python —— 括号换成花括号，交给 `format_map`**

```python
class Solution:
    def evaluate(self, s: str, knowledge: List[List[str]]) -> str:
        d = defaultdict(lambda: '?', knowledge)
        return s.replace('(', '{').replace(')', '}').format_map(d)
```
