## 0.1 2156.石子游戏 IX

Alice 和 Bob 再次设计了一款新的石子游戏。现有一行 n 个石子，每个石子都有一个关联的数字表示它的价值。给你一个整数数组 `stones` ，其中 `stones[i]` 是第 `i` 个石子的价值。

Alice 和 Bob 轮流进行自己的回合，**Alice** 先手。每一回合，玩家需要从 `stones` 中移除任一石子。

- 如果玩家移除石子后，导致 **所有已移除石子** 的价值 **总和** 可以被 3 整除，那么该玩家就 **输掉游戏** 。
- 如果不满足上一条，且移除后没有任何剩余的石子，那么 Bob 将会直接获胜（即便是在 Alice 的回合）。

假设两位玩家均采用 **最佳** 决策。如果 Alice 获胜，返回 `true` ；如果 Bob 获胜，返回 `false` 。

**示例 1：**

**输入：**stones = [2,1]
**输出：**true
**解释：**游戏进行如下：
- 回合 1：Alice 可以移除任意一个石子。
- 回合 2：Bob 移除剩下的石子。 
已移除的石子的值总和为 1 + 2 = 3 且可以被 3 整除。因此，Bob 输，Alice 获胜。

**示例 2：**

**输入：**stones = [2]
**输出：**false
**解释：**Alice 会移除唯一一个石子，已移除石子的值总和为 2 。 
由于所有石子都已移除，且值总和无法被 3 整除，Bob 获胜。

**示例 3：**

**输入：**stones = [5,1,2,4,3]
**输出：**false
**解释：**Bob 总会获胜。其中一种可能的游戏进行方式如下：
- 回合 1：Alice 可以移除值为 1 的第 2 个石子。已移除石子值总和为 1 。
- 回合 2：Bob 可以移除值为 3 的第 5 个石子。已移除石子值总和为 = 1 + 3 = 4 。
- 回合 3：Alices 可以移除值为 4 的第 4 个石子。已移除石子值总和为 = 1 + 3 + 4 = 8 。
- 回合 4：Bob 可以移除值为 2 的第 3 个石子。已移除石子值总和为 = 1 + 3 + 4 + 2 = 10.
- 回合 5：Alice 可以移除值为 5 的第 1 个石子。已移除石子值总和为 = 1 + 3 + 4 + 2 + 5 = 15.
Alice 输掉游戏，因为已移除石子值总和（15）可以被 3 整除，Bob 获胜。

**提示：**

- `1 <= stones.length <= 105`
- `1 <= stones[i] <= 104`

## 0.2 Notes

### 0.2.1 核心转化：只关心模 3

游戏胜负取决于**已移除石子总和是否能被 3 整除**。因此每个石子只需看它 `% 3` 的值：

- **类型 0**：`stones[i] % 3 == 0`，计数 `s[0]`
- **类型 1**：`stones[i] % 3 == 1`，计数 `s[1]`
- **类型 2**：`stones[i] % 3 == 2`，计数 `s[2]`

**类型 0 是"空过"石**：取出它不改变当前总和模 3 的值，只换另一方行动。游戏本质由类型 1 和类型 2 决定。

### 0.2.2 关键观察：一旦选了一个类型，后续几乎被"强制"

假设当前总和为 `x`（mod 3），如果玩家选了一个会使总和变为 0 的类型，立刻输。所以每步通常只有一种"安全"选择。

**例子**：当前总和 = 1，玩家必须选类型 1（因为选类型 2 → 1+2=3≡0，输）。

这意味着：一旦 Alice 开了第一枪，整局的取石顺序几乎是唯一确定的（双方都是理性玩家）。

### 0.2.3 情况一：`s[0]` 为偶数

偶数个类型 0 → 双方对称地使用它们来"让过"，相当于**它们不存在**，不影响先后手优势。

**Alice 首选的两种路线：**

**路线 A：Alice 先取类型 1（总和 = 1）**
```
Alice: 取 1 → 总和=1
Bob:   只能取 1（取 2 → 3≡0 输）→ 总和=2
Alice: 只能取 2（取 1 → 3≡0 输）→ 总和=1
Bob:   只能取 1 → 总和=2
Alice: 只能取 2 → 总和=1
...
```
**消耗模式**：Alice = {1 个类型 1, 剩下的全是类型 2}，Bob = {全部类型 1}

**路线 B：Alice 先取类型 2（总和 = 2）**（对称）
```
Alice: 取 2 → 总和=2
Bob:   只能取 2（取 1 → 3≡0 输）→ 总和=1
Alice: 只能取 1（取 2 → 3≡0 输）→ 总和=2
Bob:   只能取 2 → 总和=1
...
```
**消耗模式**：Alice = {1 个类型 2, 剩下的全是类型 1}，Bob = {全部类型 2}

**Alice 的最优策略**：选数量**较少**的类型开局。

- 若 `s[1] ≤ s[2]`：走路线 A，Bob 的类型 1 先耗尽 → Bob 被迫取类型 2 → 总和变 0 → Bob 输
- 若 `s[2] ≤ s[1]`：走路线 B，Bob 的类型 2 先耗尽 → Bob 被迫取类型 1 → 总和变 0 → Bob 输

**结论**：只要 `s[1] > 0 && s[2] > 0`（两种类型都存在），Alice 就能赢。

若某种类型为 0（比如只有类型 2），Alice 被迫首取类型 2，接下来双方都只能取类型 2，第二个人就会让总和变 0 而输 —— 那人恰好是 Alice。

### 0.2.4 情况二：`s[0]` 为奇数

奇数个类型 0 意味着类型 1/2 的有效先后手**反转**了一次。等价于：关于类型 1/2 的博弈中，**Bob 获得先手优势**。

Alice 虽然全局先手，但经过奇数个类型 0 的"让过"，Bob 在非零类型上占据了类似情况一中 Alice 的位置。

因此 Alice 想要赢，必须在数量上形成**压倒性差距**，让 Bob 有先手优势也赢不了。

**结论**：Alice 赢 ⇔ `|s[1] - s[2]| > 2`

具体：`s[2] > s[1] + 2` 或 `s[1] > s[2] + 2`。

为什么是 **2**？精细的回合计数可验证：差距为 2 时，Bob 的先手刚好够撑到 Alice 的某种类型先耗尽；差距超过 2 时，Alice 的压倒性数量优势让 Bob 的先手也救不了他。

### 0.2.5 总结：最终算法

```cpp
int s[3] = {0, 0, 0};
for (int i : stones) ++s[i % 3];

if (s[0] % 2 == 0) {
    // 偶数个类型 0：Alice 先手优势，只要两种类型都有就能赢
    return s[1] != 0 && s[2] != 0;
} else {
    // 奇数个类型 0：先后手反转，Alice 需要数量碾压
    return abs(s[1] - s[2]) > 2;  // 即 s[2] > s[1] + 2 || s[1] > s[2] + 2
}
```

**时间复杂度**：`O(n)`，**空间复杂度**：`O(1)`。

### 0.2.6 同系列题目

本题属于"石子游戏"系列的博弈论问题（Stone Game I ~ IX），核心思想都是将局面简化为关键状态，利用对称性和模运算减少搜索空间。

## 0.3 Solution 
```cpp
class Solution {
public:
    bool stoneGameIX(vector<int>& stones) {
        int s[3] = {0, 0, 0};
        for (int i : stones) ++s[i % 3];
        if (s[0] % 2 == 0) return s[1] != 0 && s[2] != 0;
        return s[2] > s[1] + 2 || s[1] > s[2] + 2;
    }
};
```
