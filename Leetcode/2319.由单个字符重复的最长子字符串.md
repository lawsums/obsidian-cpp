## 0.1 2319.由单个字符重复的最长子字符串

给你一个下标从 **0** 开始的字符串 `s` 。另给你一个下标从 **0** 开始、长度为 `k` 的字符串 `queryCharacters` ，一个下标从 `0` 开始、长度也是 `k` 的整数 **下标** 数组 `queryIndices` ，这两个都用来描述 `k` 个查询。

第 `i` 个查询会将 `s` 中位于下标 `queryIndices[i]` 的字符更新为 `queryCharacters[i]` 。

返回一个长度为 `k` 的数组 `lengths` ，其中 `lengths[i]` 是在执行第 `i` 个查询 **之后** `s` 中仅由 **单个字符重复** 组成的 **最长子字符串** 的 **长度** _。_

**示例 1：**

**输入：**s = "babacc", queryCharacters = "bcb", queryIndices = [1,3,3]
**输出：**[3,3,4]
**解释：**
- 第 1 次查询更新后 s = "_b**b**b_acc" 。由单个字符重复组成的最长子字符串是 "bbb" ，长度为 3 。
- 第 2 次查询更新后 s = "bbb_**c**cc_" 。由单个字符重复组成的最长子字符串是 "bbb" 或 "ccc"，长度为 3 。
- 第 3 次查询更新后 s = "_bbb**b**_cc" 。由单个字符重复组成的最长子字符串是 "bbbb" ，长度为 4 。
因此，返回 [3,3,4] 。

**示例 2：**

**输入：**s = "abyzz", queryCharacters = "aa", queryIndices = [2,1]
**输出：**[2,3]
**解释：**
- 第 1 次查询更新后 s = "ab**a**_zz_" 。由单个字符重复组成的最长子字符串是 "zz" ，长度为 2 。
- 第 2 次查询更新后 s = "_a**a**a_zz" 。由单个字符重复组成的最长子字符串是 "aaa" ，长度为 3 。
因此，返回 [2,3] 。

**提示：**

- `1 <= s.length <= 105`
- `s` 由小写英文字母组成
- `k == queryCharacters.length == queryIndices.length`
- `1 <= k <= 105`
- `queryCharacters` 由小写英文字母组成
- `0 <= queryIndices[i] < s.length`

## 0.2 Notes

### 0.2.1 线段树 vs 树状数组：为什么代码量差这么多

**本质区别**

- 树状数组（BIT）：树结构由 `lowbit` 隐式定义——`tree[i]` 覆盖区间 `[i - lowbit(i) + 1, i]`，形状完全由二进制位决定，不需要显式建树。一个数组 + 两个 while 循环就是全部。
- 线段树：显式的满二叉树，节点区间 `[l, r]` 任意对半拆，查询时把 `[l, r]` 拆成 O(log n) 个节点直接合并，合并逻辑完全由你定义。

**BIT 的代价**

- BIT 的区间查询只能走"前缀差分" `pre(r) - pre(l-1)`，这要求合并运算**可逆**（有逆元），比如加法、异或。
- 线段树不依赖差分，合并运算只需**可结合**即可：max、gcd、自定义三元组 `(mx, pre, suf)` 都行。

**代码量差异的来源**

1. BIT 的树形结构"免费"藏在 lowbit 里；线段树要 `4n` 数组 + `_build`/`_update` 递归 + 自己写 `_maintain`
2. BIT 的合并运算固定（加法）；线段树的合并是用户自定义的，本题要写三元组的合并规则
3. BIT 不用关心节点边界；线段树递归要带 `l, r, m` 参数，还得用 `s[m] == s[m+1]` 判断跨界

一句话：**BIT 是线段树的特化（只做可逆的前缀类问题），线段树是通用化（任意可结合合并）**。特化换来短代码，通用化付出长代码。能用 BIT 的题别用线段树；遇到不可逆/跨边界合并，只能上线段树。

### 0.2.2 树状数组能解决这道题吗

**结论：不能，即使 BIT 节点也维护 `(mx, pre, suf)` 三个信息也不行。**

- **机制层面**：BIT 的一切区间查询建立在"前缀差分"上，要求信息可逆。`mx` 是最大值，max 没有逆元——知道 `[1..r]` 和 `[1..l-1]` 的 mx，推不出 `[l..r]` 的 mx（这就是"区间最大值 BIT 维护不了"的经典原因）。
- **信息层面**：三个信息的合并依赖"相邻性"——左区间尾字符与右区间首字符是否相同。BIT 的 `pre` 是把若干段互不相邻的区间相加，前缀 `[1..i]` 的信息里根本不包含段与段之间的边界关系，也没法做减法还原出 `[l..r]` 的边界。
- **本质**：BIT 能维护的信息必须满足"整体 = 部分之和"的可逆合并；本题 `(mx, pre, suf)` 的合并不可逆，且答案取的是全局最大值。
- 补充：BIT 能维护 max 的场景是"只增不减 + 只查前缀"（如 LIS 优化），因为不差分就不需要逆元。本题需要跨区间拼接，正好踩在 BIT 的死穴上。
- 官方标签里的"有序集合"是另一条正解：用 set 维护相同字符连续段 + multiset 维护段长，单次更新只影响 O(1) 个段。这也从侧面说明：跨边界合并类信息需要能"自由拆分重组"的结构，BIT 的结构太死。

### 0.2.3 信息设计：节点存 `(mx, pre, suf)`

- `mx`：当前区间内最长相同字符连续段的长度（答案本体）
- `pre`：从区间左端点开始的最长相同字符连续段长度
- `suf`：到区间右端点结束的最长相同字符连续段长度

为什么是这三个：合并时"左右连在一起"的候选 = 左后缀 + 右前缀，所以节点必须记录自己的 pre 和 suf；只存 mx 不够。**设计思路：节点存什么，由 merge 需要什么倒推。**

叶子节点：`(1, 1, 1)`（单个字符，三段都是 1）。

### 0.2.4 合并规则（`_maintain` 的核心）

设 `same = (s[m] == s[m+1])`，即左区间尾字符与右区间首字符相同。左右信息为 `(left_mx, left_pre, left_suf)`、`(right_mx, right_pre, right_suf)`。

**mx 的三个候选，取最大：**

1. 仅左边：`left_mx`
2. 仅右边：`right_mx`
3. 左右连在一起：`same` 时 `left_suf + right_pre`，否则不存在

**pre 的更新：**

- 能连接的条件（两个同时满足）：
  1. 左边的前缀已经覆盖整个左区间：`left_pre == m - l + 1`（左区间全部相同）
  2. 边界字符相同：`same`
- 满足 → `pre = left_pre + right_pre`；否则 → `pre = left_pre`（连不起来，只能取左边的前缀）

**suf 的更新（对称反过来）：**

- 条件：`right_suf == r - m`（右区间全部相同）且 `same`
- 满足 → `suf = right_suf + left_suf`；否则 → `suf = right_suf`

**实现细节：**

- 判断 `same` 要访问原始数组，所以模板里保存了 `self._s`；叶子节点只存长度，不存字符
- 单点更新：把叶子改成 `(1, 1, 1)`，回溯时沿途 `_maintain`，一次更新只重算 O(log n) 个节点
- 查询答案：全局最大 = 根节点的 `mx`，即 `tree[1][0]`

## 0.3 Solution 
```python
class SegmentTree:
    def __init__(self, s: list[str]):
        self._n = len(s)
        self._s = s  # 保存原始数组，用于在 _maintain 中判断边界字符
        # 初始化树数组，大小为 4*n 足够
        self._tree = [None] * (4 * self._n)
        self._build(1, 0, self._n - 1)

    # 1. 修正 _merge_val: 只负责合并两个值（在这里是长度），取最大值
    def _merge_val(self, a: int, b: int) -> int:
        return max(a, b)

    # 2. 修正 _maintain: 负责整合左右子树的全部信息
    def _maintain(self, node: int, l: int, m: int, r: int) -> None:
        # 从左右子节点获取完整的 (max_len, pre_len, suf_len) 信息
        left_mx, left_pre, left_suf = self._tree[node * 2]
        right_mx, right_pre, right_suf = self._tree[node * 2 + 1]

        # 判断左右区间在中间是否可以连接
        same = self._s[m] == self._s[m + 1]

        # 计算当前节点的最大长度
        # 可能是左边的最大值，右边的最大值，或者跨越中间的长度 (left_suf + right_pre)
        mx = self._merge_val(self._merge_val(left_mx, right_mx), left_suf + right_pre if same else 0)

        # 计算当前节点的前缀长度
        # 如果左边整个区间都是相同字符，并且能和右边前缀连接，则前缀长度要加上右边的前缀长度
        pre = left_pre + right_pre if same and left_pre == m - l + 1 else left_pre

        # 计算当前节点的后缀长度
        # 如果右边整个区间都是相同字符，并且能和左边后缀连接，则后缀长度要加上左边的后缀长度
        suf = right_suf + left_suf if same and right_suf == r - m else right_suf

        self._tree[node] = (mx, pre, suf)

    def _build(self, node: int, l: int, r: int) -> None:
        if l == r:  # 叶子节点
            # 叶子节点的长度、前缀、后缀都是 1
            self._tree[node] = (1, 1, 1)
            return
        
        m = (l + r) // 2
        self._build(node * 2, l, m)
        self._build(node * 2 + 1, m + 1, r)
        # 调用 _maintain 时需要传入区间信息 l, m, r
        self._maintain(node, l, m, r)

    def _update(self, node: int, l: int, r: int, i: int, val: str) -> None:
        if l == r:  # 叶子节点
            self._s[i] = val # 更新原始数组
            # 叶子节点的值重置为 (1, 1, 1)
            self._tree[node] = (1, 1, 1)
            return
        
        m = (l + r) // 2
        if i <= m:
            self._update(node * 2, l, m, i, val)
        else:
            self._update(node * 2 + 1, m + 1, r, i, val)
        
        # 更新完子节点后，重新维护当前节点
        self._maintain(node, l, m, r)

    def update(self, i: int, val: str) -> None:
        self._update(1, 0, self._n - 1, i, val)

    def query_all(self) -> int:
        # 根节点（下标为1）存储了整个区间的最大长度信息
        return self._tree[1][0]

class Solution:
    def longestRepeating(self, s: str, queryCharacters: str, queryIndices: List[int]) -> List[int]:
        t = SegmentTree(list(s))
        ans = []
        for i, ch in zip(queryIndices, queryCharacters):
            t.update(i, ch)
            ans.append(t.query_all())
        return ans
```
