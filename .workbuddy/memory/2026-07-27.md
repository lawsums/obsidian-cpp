# 2026-07-27 工作日志

## ACGbangumi-cli.cjs 修复

- **linkedom 懒加载**：原来是模块顶层 `const { parseHTML } = loadLinkedom()` ——如果 linkedom 找不到，连 `--help` 都直接 exit(2) 没机会输出。改成 `getParseHTML()` 懒加载，只在 `parseHtmlToDom` 首次调用时才加载。`--help` / `search`（不解析 HTML 时）完全不受 linkedom 影响。
- 另一个 Agent 跑 `--help` 没输出 — 是它自己的 PowerShell stdout 捕获问题（`echo "hello world"` 也出不来），不是脚本 bug。本 WorkBuddy 环境验证 `--help` 正常，exit 0，输出完整。

## Agent 调用协议

用户反馈 Obsidian 内嵌 Agent 调用脚本很麻烦（路径混乱、输出捕获不到）。创建了两个辅助文件：

- **`ACGbangumi.cmd`** — Windows 批处理包装器。Agent 用 PowerShell 调 `cmd.exe /c ACGbangumi.cmd --help` 或直接在调用时指定 `.cmd`，比裸 `node script.cjs` 更稳定（CMD 子进程 stdout 不受 PowerShell 宿主捕获问题影响）。自动 cd 到脚本目录、优先用 workbuddy 托管 node。
- **`ACGbangumi-API.md`** — 完整的调用协议文档。Agent 可加载为上下文，含所有子命令、参数表、示例流程、输出路径约定。用户只需让 Agent 读这个文件就知道怎么调。
