# 3 为什么要使用 FastCGI？
## 3.1 一句话答案：
**让 Nginx 能调用 C/C++ 写的后台程序，处理登录、注册、上传、下载。**

## 3.2 详细解释（你必须懂）
- Nginx 本身**不能运行 C 语言程序**
- 但你的网盘登录/注册/上传都是 **C 语言写的**
- FastCGI 就是 **Nginx 和 C 程序之间的桥梁**

## 3.3 流程
```
浏览器 → Nginx → FastCGI → 你的 C 程序（login/reg/upload）
```

## 3.4 作用
- 支持高并发
- 让 C 语言写后台服务
- 适合网盘这种高性能项目

# 4 为什么要使用 FastDFS？
## 4.1 一句话答案：
**专门用来存海量小文件（图片、文件、视频），超级快、永不宕机。**

## 4.2 详细解释
普通服务器存文件会遇到问题：
- 单目录文件太多，打开慢
- 硬盘满了无法扩展
- 下载速度慢

FastDFS 解决：
- 分布式存储
- 自动扩容
- 下载速度快
- 网盘必备的文件存储中间件

## 4.3 你网盘里的作用
**所有用户上传的文件，都存在 FastDFS 里。**

# 5 为什么要使用 Nginx？
## 5.1 一句话答案：
**高性能 Web 服务器，接收用户请求，转发给后台服务，提供文件下载。**

## 5.2 作用
1. **接收浏览器/Qt客户端请求**
2. **路由请求**
   - /login → 登录服务
   - /reg → 注册服务
   - /group1/M00 → 图片/文件下载
3. **高并发、稳定、轻量**
4. **配合 FastDFS 提供文件 HTTP 访问**

## 5.3 你网盘里的角色
**整个项目的入口大门！**

# 6 为什么要同时使用 Redis + MySQL？
## 6.1 一句话答案：
**MySQL 存永久数据，Redis 存高速缓存，各司其职，配合无敌。**

## 6.2 详细解释

### 6.2.1 MySQL（硬盘存储，永久保存）
存：
- 用户账号密码
- 用户文件列表
- 分享记录
- 所有需要**永久保存**的数据

### 6.2.2 Redis（内存存储，超级快）
存：
- 用户登录 Token（会话）
- 文件 MD5 去重
- 热点数据
- 需要**极高速度**读取的数据

## 6.3 为什么要一起用？
1. **MySQL 可靠但慢**
2. **Redis 极快但断电丢失**
3. 网盘项目：
   - 登录、token、md5 → 放 Redis
   - 用户信息、文件列表 → 放 MySQL

## 6.4 你项目里的真实用途
- **MySQL**：存用户、文件列表
- **Redis**：存登录状态、文件 MD5 秒传判断
