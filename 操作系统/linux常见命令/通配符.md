## 原理
通配符具有**参数拓展**的作用, 比如说以下这个简单的 c程序用于显示所有输入参数
```cpp
int main(int argc, char **argv)
{
    int i = 0;
    for (i = 0; i < argc; ++i) {
        printf("argv[%d]: %s\n", i, argv[i]);
    }
    return 0;
}
```

以下为输出结果
```ruby
lawsam@ubuntu2:~/CPP62/playground$ ls
11.txt  1.txt  2.txt  3.txt  a.out  main.c  test.sh
lawsam@ubuntu2:~/CPP62/playground$ ./a.out *.txt
argv[0]: ./a.out
argv[1]: 11.txt
argv[2]: 1.txt
argv[3]: 2.txt
argv[4]: 3.txt
lawsam@ubuntu2:~/CPP62/playground$ 
```
说明*.txt不仅是展开成字符串, 而且是以空格间隔的形式展开的, 所以能被接受成多个参数

同时我们还可以这样
```ruby
lawsam@ubuntu2:~/CPP62/playground$ ./a.out {1..9}.txt
argv[0]: ./a.out
argv[1]: 1.txt
argv[2]: 2.txt
argv[3]: 3.txt
argv[4]: 4.txt
argv[5]: 5.txt
argv[6]: 6.txt
argv[7]: 7.txt
argv[8]: 8.txt
argv[9]: 9.txt
```

通过`{num1..num2}`的方式传入一个range范围, 我想称其为**循环折叠**

你需要shell中通配符的**完整类型、核心作用**，还会结合你之前实操的 `[12].txt` / `[12]?.txt` 等场景举例，同时标注**使用频率、核心误区、搭配技巧**，所有内容贴合bash（Ubuntu默认shell），是最实用的基础通配符总结，先给核心通配符（高频使用），再补充扩展通配符（进阶场景），最后加避坑和实操对比，方便你直接套用。

### 一、Shell基础通配符（高频必会，80%场景够用）
bash最核心的5个通配符，**仅匹配文件名/目录名**，由shell先解析再传参（你之前的C++程序传参就是这个逻辑），每个都标注**符号、含义、实操例子**（基于你目录的`1.txt`/`2.txt`/`11.txt`/`12.txt`/`3.txt`），方便对照理解。

| 符号 | 官方名称 | 核心作用 | 实操例子（你的场景） | 匹配结果 |
|------|----------|----------|----------------------|----------|
| `*`  | 星号     | 匹配**0个或多个任意字符**（长度无限制，包括空） | `*.txt` | 所有`.txt`文件（1/2/11/12/3.txt） |
| `?`  | 问号     | 匹配**恰好1个任意字符**（必须有1个，不能空、不能多） | `[12]?.txt` | 仅11.txt、12.txt（1/2+1个任意字符+.txt） |
| `[]` | 方括号   | 匹配**括号内任意1个字符**（字符集），支持单字符/字符范围 | `[12].txt`「单字符」<br>`[1-2].txt`「范围」 | 1.txt、2.txt（两种写法效果一致） |
| `[^]`/`![]` | 否定方括号 | 匹配**括号内以外的任意1个字符**（对[]取反），`^`是标准写法，`!`是bash兼容写法 | `[^12].txt` | 仅3.txt（排除1/2开头的单字符.txt） |
| `-`  | 连字符   | 配合[]使用，定义**连续的字符范围**（数字/字母），无[]时是普通字符 | `[1-3].txt`「数字范围」<br>`[a-c].txt`「字母范围」 | 1/2/3.txt（匹配1-3的单字符.txt） |

#### 基础通配符关键细节（避坑）
1. `*`是**最宽松**的匹配，可匹配空字符（比如`[12]*.txt`中，`1.txt`的`*`就匹配空）；
2. `?`是**严格单字符占位**，你之前误以为是「重复匹配」，核心误区就是把它和正则的`+`/`?`混淆；
3. `[]`内的字符**无顺序**，`[12]`和`[21]`效果一致，且仅匹配**1个字符**；
4. 连字符`-`**必须在[]内才有效**，单独写`mkdir a-b`会创建名为`a-b`的目录，不是`a`和`b`；
5. 否定匹配中，`^`**必须是[]内第一个字符**才有效，`[1^2]`不是取反，而是匹配`1`/`^`/`2`三个字符。

### 二、Shell扩展通配符（进阶，需开启extglob，适合复杂匹配）
基础通配符无法实现「匹配1次或多次」「匹配0次或1次」等复杂逻辑，bash提供**扩展通配符（extglob）**，完美弥补这个缺陷，**可直接实现你之前想要的「一个或多个[]内字符」**，无需用`[12][12]*`的组合写法。

#### 第一步：开启扩展通配符（bash默认关闭，临时/永久开启）
```bash
# 临时开启（仅当前终端有效，重启后失效，推荐测试/临时使用）
shopt -s extglob
# 永久开启（所有终端生效，需重新登录，推荐开发使用）
echo "shopt -s extglob" >> ~/.bashrc && source ~/.bashrc

# 验证是否开启（输出on表示成功）
shopt extglob
# 关闭扩展通配符（如需）
shopt -u extglob
```

#### 第二步：5个扩展通配符（核心解决「重复匹配」「多选择」）
开启extglob后，可使用以下通配符，**直接实现正则的核心匹配逻辑**，结合你的`1/2`场景举例，彻底解决你之前的「一个或多个」需求。

| 符号 | 含义 | 核心作用 | 实操例子（你的场景） | 匹配结果 |
|------|------|----------|----------------------|----------|
| `?(pattern)` | 可选匹配 | 匹配pattern**0次或1次**（正则`?`） | `1?(1).txt` | 1.txt、11.txt（1后跟0/1个1） |
| `*(pattern)` | 任意匹配 | 匹配pattern**0次或多次**（正则`*`） | `[12]*(12).txt` | 1/2/11/12/1212.txt（1/2后跟0/多组12） |
| `+(pattern)` | 至少一次 | 匹配pattern**1次或多次**（正则`+`） | `+([12]).txt` | 1/2/11/12/222.txt（1/2出现1+次，你最想要的！） |
| `@(pattern)` | 精确匹配 | 匹配pattern**恰好1次**（多选择匹配） | `@(1|2).txt` | 1.txt、2.txt（等价于[12].txt，支持多规则） |
| `!(pattern)` | 否定匹配 | 匹配**除pattern外的所有内容**（全局取反） | `!(*.txt)` | 所有非.txt文件（比如1.sh、2.py） |

#### 扩展通配符核心亮点（贴合你的需求）
✅ 你之前想要的**「匹配一个或多个[]内的字符（1/2）」**，用`+(pattern)`直接实现：
```bash
# 开启extglob后，一行匹配所有1/2出现1+次的.txt文件，无需组合写法
./a.out +([12]).txt
# 匹配结果：1.txt、2.txt、11.txt、12.txt、222.txt（完美契合你的核心需求）
```
这是**最标准、最简洁**的实现方式，比基础通配符的`[12][12]*.txt`更直观，完全对应正则的`[12]+`。

### 三、Shell通配符核心使用原则（避坑+实操）
1. **shell先解析，程序后接收**：所有通配符由bash先解析为具体文件名，再传给程序（比如你的C++程序），程序拿到的是`1.txt`而非`[12].txt`；若想让程序自己解析，用**单/双引号包裹通配符**：
   ```bash
   ./a.out "[12].txt" # shell不解析，argv[1]直接是[12].txt
   ```
2. **匹配失败不解析**：如果没有匹配的文件，shell会将原始通配符直接传给程序，比如：
   ```bash
   ./a.out [34].txt # 无3.txt/4.txt，argv[1]是[34].txt
   ```
3. **按ASCII字典序排序**：shell匹配后的文件会按ASCII码排序，数字按**单个字符比较**（比如`11.txt`在`1.txt`前，因为`1`的ASCII码小于`.`）；
4. **通配符≠正则表达式**：这是最核心的误区，两者语法完全独立（比如shell`*`是任意字符，正则`*`是前一个字符0+次；shell`?`是单字符，正则`?`是前一个字符0/1次），**仅[]/[^]规则基本一致**；
5. **仅匹配文件名，不匹配内容**：shell通配符仅用于匹配**当前/指定目录的文件名/目录名**，不能匹配文件内容（匹配内容需用grep/awk等工具结合正则）。

### 四、实操对比：基础通配符 vs 扩展通配符（实现「一个或多个1/2」）
结合你最核心的需求，对比两种实现方式，看扩展通配符的简洁性：
```bash
# 场景：匹配1/2出现1+次的.txt文件（目录有1/2/11/12/222/3.txt）
## 基础通配符（无需开启任何配置，兼容所有shell）
./a.out [12][12]*.txt
## 扩展通配符（开启extglob，简洁直观，对应正则[12]+）
shopt -s extglob && ./a.out +([12]).txt
# 两种写法匹配结果完全一致：1/2/11/12/222.txt
```

### 五、Shell通配符高频实用组合（直接套用）
结合开发场景，整理你最可能用到的组合写法，基于你的C++文件操作需求：
1. 匹配**以1/2开头，任意后缀**的文件：`[12]*`
2. 匹配**以1/2结尾，任意前缀**的文件：`*[12]`
3. 匹配**1/2开头，数字结尾，.txt后缀**的文件：`[12]*[0-9].txt`
4. 匹配**仅由数字组成，.txt后缀**的文件：`+([0-9]).txt`（扩展通配符）
5. 匹配**排除1/2开头**的所有.txt文件：`[^12]*.txt`

### 核心总结
1. **基础通配符**：`*`/`?`/`[]`/`[^]`/`-`是必会内容，80%场景够用，核心是**字符占位/字符集匹配**，无原生重复匹配能力；
2. **扩展通配符**：开启`extglob`后可用`+()`/`*()`/`?()`，完美实现**重复匹配**（比如`+([12])`就是1/2出现1+次），是你核心需求的最优解；
3. **核心误区**：shell通配符≠正则，仅[]规则一致，`*`/`?`在两者中含义完全不同；
4. **解析规则**：shell先解析通配符为具体文件，再传参给程序，引号可屏蔽解析；
5. **你的核心需求**：实现「一个或多个[]内字符」，要么用基础通配符`[字符集][字符集]*`，要么开启extglob用`+([字符集])`（更简洁）。
