# 20亿整数找众数：超详细分治法完整解答
我给你把**分治全流程、内存计算、分片规则、40亿+long long扩容**全部讲透，完全是面试满分标准答案，可直接背诵。

---

## 一、题目核心前提
- 内存：**2GB**
- 数据量：**20亿 整数**
- 目标：**找出现次数最多的数（众数）**
- 限制：**无法一次性加载全部数据进内存**

---

## 二、关键内存计算（面试必问）
### 1. 单条 key-value 占用字节数
我们用**哈希表（字典）**存储：
`key = 整数值`，`value = 出现次数`

- 32位 int  key：**4字节**
- 32位 int 计数：**4字节**
- 哈希表结构额外开销（指针/链表）：约 **8字节**
👉 **一对 key-value 总占用 ≈ 16字节**

### 2. 2GB 内存最多存多少条记录？
2GB = 2 * 1024MB = 2 * 1024 * 1024KB = **2^31 字节**
可存储键值对数量：
`2^31 / 16 ≈ 1.3亿 条`

### 3. 数据规模结论
- 20亿整数 ≠ 20亿唯一数
- 但**最坏情况**：20亿全不重复
- 2GB 最多存 **1.3亿唯一数**
👉 **必须分片！必须分治！**

---

## 三、分治法完整执行流程
### 步骤1：确定分片数量（均匀分配）
目标：让每个分片的**唯一数数量 < 1.3亿**

计算公式：
`分片数 n = 总数据量 / 单机最大承载量`
`n = 20亿 / 1.3亿 ≈ 16片`

👉 **分成 16~20 个小文件即可**（留安全冗余）

### 步骤2：哈希取模均匀分片（最关键）
**如何保证数据平均分配到n个子问题？**
使用**哈希取模**：
```
分片编号 = hash(数字) % 总片数n
```
- 相同数字一定进入**同一个分片**
- 不同数字均匀打散
- 无数据倾斜，每个分片大小基本一致

### 步骤3：逐片加载统计（子问题求解）
循环处理每个小文件：
1. 读入一个小文件到内存
2. 用字典`{数字:次数}`统计频率
3. 保存当前分片的`{数字:总次数}`到磁盘
4. 清空内存，处理下一个分片

👉 每个子问题数据规模：**约1~1.25亿条整数**
👉 每个子问题唯一数：**≤1亿**，完全在2GB内

### 步骤4：合并所有分片结果
1. 读取16个分片的统计结果
2. 对**相同数字**的次数累加
3. 遍历找到次数最大的数字

---

## 四、数据规模变化：20亿 → 40亿
### 1. 数据量翻倍，分片数直接翻倍
- 20亿 → 16~20片
- 40亿 → **32~40片**
流程完全不变，只是循环次数变多。

### 2. 从 int 换成 long long 的影响
`long long` = 64位整数 = **8字节**

#### 内存占用变化：
- int key：4字节 → long long：8字节
- 单条 key-value：16字节 → **24字节**
- 2GB 可存记录数：1.3亿 → **≈8500万**

#### 应对方案：
1. **分片数略微增加**
   - 8500万/片 → 40亿数据需要 **≈48片**
2. **统计逻辑完全不变**
3. **计数value仍可用int**
   40亿数据，一个数最多出现40亿次
   - int 最大：21亿（不够）
   - 所以**value也必须换成 long long**
👉 最终：key=long long，value=long long
**单条占用 8+8+8=24字节**

---

## 五、最终标准答案（可背诵版）
## 标准答案
核心结论：采用**哈希取模分治+哈希表统计**，将20亿整数通过`hash(num)%n`均匀分配到16~20个小分片，单机逐片加载并用字典统计频率，最后合并结果得到众数；解决**海量数据超出单机内存无法直接处理**的问题，具备**内存可控、无数据倾斜、通用可扩容**的核心特性。
