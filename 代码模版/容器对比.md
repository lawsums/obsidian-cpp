### 主流容器/并发类型 - C++/Python/Go 对应表
我会按**语言原生支持（优先）> 标准库/内置包**的原则填充，兼顾**常用性**和**语义匹配**，并发相关（线程、锁）补充核心使用方式，Go 部分贴合其「内置并发原语」的设计特点，C++ 标注常用标准库容器，Python 区分内置类型和标准库 `collections`/`threading` 包。

| 容器类型/语言 | C++（C++11/17 标准库）| Python（内置/标准库）| Golang（内置/标准库）|
| ------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 数组          | 原生数组`T[N]`、`std::array<T,N>`（固定长度，栈/全局）| 原生`list`（伪数组，实则动态数组）、`array.array`（纯数值固定数组，标准库） | 原生数组`[N]T`（固定长度，值类型）|
| 动态数组      | `std::vector<T>`（最核心，连续内存）| 原生`list`（核心动态数组，链表实现）、`collections.deque`（双端动态数组，高效增删） | 原生切片`[]T`（核心动态数组，基于底层数组的引用类型）|
| 哈希表        | `std::unordered_map<K,V>`（无序哈希表，C++11+）、`std::unordered_multimap`（允许重复键） | 原生`dict`（核心无序哈希表，键唯一）| 原生`map[K]V`（无序哈希表，键唯一，运行时安全）、`sync.Map`（标准库`sync`，并发安全哈希表） |
| 栈            | `std::stack<T>`（适配器，默认基于`deque`实现）| `collections.deque`（用`append/pop`模拟，高效）、原生`list`（`append/pop`，尾增删） | 无原生栈类型，用**切片`[]T`**模拟（`append`入栈/`s[:len(s)-1]`出栈，最常用） |
| 有序集合      | `std::set<T>`（红黑树，有序唯一）、`std::multiset<T>`（有序可重复） | 无原生，`bisect`模块+`list`实现有序集合、第三方`SortedContainers` | 无原生标准库，需自定义（红黑树/跳表）、第三方库实现；可通过`map`+手动排序模拟简易有序集合 |
| 集合          | `std::unordered_set<T>`（哈希集合，无序唯一，C++11+）、`std::multiset`（有序可重复） | 原生`set`（无序哈希集合，键唯一）、`frozenset`（不可变集合） | 无原生集合类型，用**`map[T]struct{}`**模拟（值用空结构体节省内存，最常用） |
| 队列          | `std::queue<T>`（适配器，默认基于`deque`，FIFO）| `collections.deque`（用`append/popleft`模拟，高效FIFO）、`queue.Queue`（标准库，线程安全） | 无原生队列，标准库`container/list`（双向链表）模拟、`channel`（通道，天然FIFO，并发场景首选） |
| 双端队列      | `std::deque<T>`（双端队列，首尾增删O(1)）| `collections.deque`（核心双端队列，首尾增删O(1)，原生高效） | 无原生双端队列，标准库`container/list`（双向链表，模拟双端队列）、切片手动模拟（首增删低效） |
| 线程          | `std::thread`（C++11+，标准库`<thread>`）| `threading.Thread`（标准库，轻量线程）、`multiprocessing.Process`（进程，规避GIL） | 原生**goroutine**（协程，关键字`go`启动，轻量）、标准库`os/exec`（外部进程）、`sync`辅助协程同步 |
| 锁            | `std::mutex`（互斥锁）、`std::recursive_mutex`（递归锁）、`std::lock_guard`（自动解锁，`<mutex>`） | `threading.Lock`（互斥锁）、`threading.RLock`（递归锁）、`threading.Semaphore`（信号量） | 标准库`sync`包：`sync.Mutex`（互斥锁）、`sync.RWMutex`（读写锁）、`sync.WaitGroup`（协程等待）；`sync.Once`（单次执行） |

### 关键补充说明（避坑/核心用法）
#### 1. Go 无原生类型的替代方案（开发高频用）
Go 设计上**不提供冗余的容器封装**，靠基础类型模拟高频容器，这是Go的核心设计特点，记住2个最常用模拟：
- **集合**：`map[int]struct{}{}`（空结构体`struct{}`无内存占用，比`map[int]bool`更高效），示例：
  ```go
  // 字符串集合
  set := make(map[string]struct{})
  set["a"] = struct{}{} // 加入集合
  _, ok := set["a"]     // 判断是否存在（ok=true则存在）
  delete(set, "a")      // 从集合删除
  ```
- **栈/队列**：栈直接用切片，队列**并发场景用channel**（天然安全），单协程用`container/list`。

#### 2. 各语言「核心容器」重点
- C++：**`vector`/`unordered_map`/`deque`** 是开发中90%场景的首选，适配器（`stack`/`queue`）基于基础容器实现；
- Python：**`list/dict/set/deque`** 覆盖几乎所有容器需求，`deque`是双端操作/队列的最优解；
- Go：**切片`[]T`/`map[K]V`/channel/goroutine** 是四大核心，几乎所有复杂逻辑都基于这四个原生类型实现。

#### 3. 并发相关的语言差异
- C++/Python 的「线程」是**操作系统级线程**（重量，切换成本高），Python 因GIL限制，多线程无法利用多核，需用多进程；
- Go 的**goroutine**是**用户级协程**（轻量，初始栈仅2KB，支持十万级并发），由Go运行时调度，无需开发者关心内核线程，是Go并发的核心优势。

#### 4. 有序集合的特殊说明
Python/Go 均无**原生标准库有序集合**，若业务需要高性能有序集合（如排序、范围查询），Python 可使用第三方库 `SortedContainers`，Go 可使用开源红黑树/跳表实现（如 `github.com/emirpasic/gods`），日常简易场景可通过「基础容器+手动排序」实现。
