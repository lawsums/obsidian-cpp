要理解 Makefile 能把 `.nas`（汇编源码）编译成 `.img`（磁盘镜像），核心是**Makefile 定义了一套「流水线式的编译规则」** —— 把“汇编 → 二进制 → 镜像”的多个步骤串起来，`make` 工具会按依赖关系自动执行这些步骤。

我会从「核心逻辑+逐步骤拆解」两部分讲清楚，结合你 `harib00a` 的 Makefile 实例，新手也能看懂。

### 0.1.1 一、核心原理：Makefile 的「依赖+规则」机制
Makefile 的本质是**“目标-依赖-命令”** 三件套：
```makefile
目标: 依赖文件
	执行的命令
```
- **目标**：最终要生成的文件（比如 `ipl.bin`、`haribote.img`）；
- **依赖**：生成这个目标需要的前置文件（比如 `ipl.nas` 是 `ipl.bin` 的依赖）；
- **命令**：从依赖生成目标的具体操作（比如用汇编器把 `.nas` 转 `.bin`）。

`make` 工具会自动分析依赖关系：
1. 检查“目标文件”是否存在，或是否比“依赖文件”旧；
2. 如果目标不存在/依赖更新了，就执行对应的命令生成目标；
3. 按“从最终目标倒推”的顺序执行（比如要生成 `haribote.img`，先检查 `ipl.bin` 是否存在，不存在就先编译 `ipl.bin`）。

你的 `.nas` → `.img` 就是靠这套机制，把“汇编→二进制→镜像”的步骤串起来了。

### 0.1.2 二、逐步骤拆解：.nas → .img 的完整流程

^a02d02

结合你 `harib00a` 的 Makefile，我把整个过程拆成 3 个核心步骤，每个步骤对应 Makefile 里的一条规则：

#### 0.1.2.1 步骤 1：.nas（汇编源码）→ .bin（二进制机器码）
这是最基础的“汇编编译”步骤，对应 Makefile 里的 `ipl.bin` 规则：
```makefile
# 定义汇编器路径（nask 是书中定制的简易汇编器）
AS = ../z_tools/nask.exe

# 目标：ipl.bin；依赖：ipl.nas；命令：用nask编译nas成bin
ipl.bin: ipl.nas
	$(AS) ipl.nas ipl.bin ipl.lst
```
- **作用**：把人类能看懂的汇编代码（`ipl.nas`），转换成 CPU 能执行的二进制机器码（`ipl.bin`）；
- **工具**：`nask.exe` 是《30天自制操作系统》作者定制的 16位汇编器，专门适配操作系统引导程序（IPL）的编译；
- **产物**：
  - `ipl.bin`：512字节的二进制文件（MBR/主引导记录，磁盘第一个扇区）；
  - `ipl.lst`：编译清单（可选，用于调试，记录汇编代码和机器码的对应关系）。

#### 0.1.2.2 步骤 2：.bin（二进制）→ .img（磁盘镜像）
这一步是把二进制文件“写入”到空的磁盘镜像模板里，对应 `haribote.img` 规则：
```makefile
# 定义镜像制作工具路径
EDIMG = ../z_tools/edimg.exe

# 目标：haribote.img；依赖：ipl.bin；命令：用edimg制作镜像
haribote.img: ipl.bin
	$(EDIMG) imgin:../z_tools/fdimg0at.tek \  # 空的软盘镜像模板
		wbinimg src:ipl.bin len:512 from:0 to:0 \  # 把ipl.bin写入镜像的0扇区，长度512字节
		imgout:haribote.img  # 输出最终的镜像文件
```
- **核心逻辑**：
  1. 先拿一个空白的软盘镜像模板（`fdimg0at.tek`）；
  2. 把 `ipl.bin`（512字节）精确写入到镜像的“第0扇区”（磁盘引导区的固定位置）；
  3. 生成可被模拟器（QEMU）识别的软盘镜像 `haribote.img`。
- **工具**：`edimg.exe` 是书中定制的镜像编辑工具，专门用来把二进制文件写入磁盘镜像的指定位置。

#### 0.1.2.3 步骤 3：统一入口（img 目标）：串联所有步骤
Makefile 里还定义了一个“总入口” `img` 目标，方便你一键执行：
```makefile
img:
	../z_tools/make.exe -r haribote.img
```
- **作用**：执行 `make img` 时，`make` 会自动去执行 `haribote.img` 规则；
  而执行 `haribote.img` 规则前，又会先检查 `ipl.bin` 是否存在，不存在就先执行 `ipl.bin` 规则；
  最终自动完成「`ipl.nas` → `ipl.bin` → `haribote.img`」的全流程。

### 0.1.3 三、关键补充：为什么是这些工具？
你可能会问“为什么不用 gcc、ld 这些常见工具？”—— 因为操作系统的**引导程序（IPL）有特殊要求**：
1. IPL 必须是 16位实模式代码（gcc 默认编译 32/64位保护模式代码）；
2. IPL 必须刚好 512 字节，且最后两个字节是 `0x55AA`（磁盘引导区的标志）；
3. 必须精确写入磁盘镜像的第0扇区，普通编译工具做不到。

所以作者定制了 `nask.exe`（适配16位汇编）和 `edimg.exe`（适配镜像写入），而 Makefile 只是把这些工具的调用规则“固化”下来，让你不用手动敲每一条命令。

### 0.1.4 总结
1. Makefile 能实现 `.nas` → `.img`，核心是**依赖+规则**机制：按“最终目标倒推”，自动执行每一步编译/打包命令；
2. 核心流程分两步：`nask.exe` 把 `.nas` 汇编成 `.bin`（机器码），`edimg.exe` 把 `.bin` 写入空白镜像模板生成 `.img`；
3. 定制工具（nask/edimg）是关键：适配操作系统引导程序的16位、512字节、扇区写入等特殊要求。

简单说：Makefile 是“指挥官”，按依赖关系指挥 `nask`/`edimg` 这些“工人”，一步步把汇编源码变成可运行的磁盘镜像。
